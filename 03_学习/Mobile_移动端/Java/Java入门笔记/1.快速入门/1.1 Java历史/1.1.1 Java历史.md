## 2. Java 语言特性

### 编译型 vs 解释型 vs Java

| 类型 | 代表语言 | 执行方式 | 优缺点 |
|------|----------|----------|--------|
| 编译型 | C、C++ | 直接编译成机器码执行 | 快，但需为每个平台单独编译 |
| 解释型 | Python、Ruby | 解释器直接加载源码运行 | 跨平台，但运行效率低 |
| Java | Java | 编译为字节码，由 JVM 执行 | 兼顾跨平台和性能 |

### 核心理念："一次编写，到处运行"

```
源代码(.java) → 编译器 → 字节码(.class) → JVM → 机器码执行
```

- Java 源码编译为**字节码**（类似抽象 CPU 指令）
- 不同平台有各自的 JVM 负责加载和执行字节码
- SUN 公司制定了 JVM 规范，保证各平台兼容性
- 低版本字节码可在高版本 JVM 上正常运行

## 3. Java 三大版本

```
┌───────────────────────────┐
│ Java EE                   │
│    ┌────────────────────┐ │
│    │ Java SE            │ │
│    │    ┌─────────────┐ │ │
│    │    │  Java ME    │ │ │
│    │    └─────────────┘ │ │
│    └────────────────────┘ │
└───────────────────────────┘
```

| 版本      | 全称                 | 定位   | 说明                                  |
| ------- | ------------------ | ---- | ----------------------------------- |
| Java SE | Standard Edition   | 标准版  | 包含标准 JVM 和标准库，是整个 Java 平台的核心        |
| Java EE | Enterprise Edition | 企业版  | 在 SE 基础上加大量 API 和库，用于 Web、数据库、消息服务等 |
| Java ME | Micro Edition      | 嵌入式版 | "瘦身版"，标准库和 JVM 都做了裁剪，已基本被淘汰         |

**要点：**
- Java EE 使用的 JVM 和 Java SE 完全相同
- Java ME 的 JVM 是独立的"瘦身版"，与 SE 不兼容
- Spring 等框架属于 Java EE 开源生态系统
- 移动开发已被 Android 取代，无需学习 Java ME

Java SE（基础，必学）

## 6. 核心名词解释

### JDK 与 JRE

```
  ┌─    ┌──────────────────────────────────┐
  │     │     Compiler, debugger, etc.     │
  │     └──────────────────────────────────┘
 JDK ┌─ ┌──────────────────────────────────┐
  │  │  │                                  │
  │ JRE │      JVM + Runtime Library       │
  │  │  │                                  │
  └─ └─ └──────────────────────────────────┘
```

| 名词 | 全称 | 作用 |
|------|------|------|
| JDK | Java Development Kit | 开发工具包，包含 JRE + 编译器 + 调试器等 |
| JRE | Java Runtime Environment | 运行环境，包含 JVM + 运行时库 |
| JVM | Java Virtual Machine | 负责执行字节码的虚拟机 |

**关系：** JDK ⊃ JRE ⊃ JVM

> 开发 Java 程序需要安装 JDK；仅运行 Java 程序只需 JRE。

### JSR 与 JCP

| 名词 | 全称 | 作用 |
|------|------|------|
| JSR | Java Specification Request | Java 规范提案，定义标准接口 |
| JCP | Java Community Process | 负责审核 JSR 的组织 |
| RI | Reference Implementation | 参考实现（能跑的正确代码，不追求性能） |
| TCK | Technology Compatibility Kit | 兼容性测试套件，验证实现是否符合规范 |

**JSR 的意义：** 统一接口标准，避免厂商锁定。例如数据库驱动遵循 JDBC 规范，开发者的代码可以在 MySQL 和 PostgreSQL 间切换而无需修改。

## 7. 关键总结

1. Java 是介于编译型和解释型之间的语言，通过字节码 + JVM 实现跨平台
2. Java SE 是一切的基础，必须优先掌握
3. 学习 Java 开发需要安装 JDK（不仅仅是 JRE）
4. JSR 规范保证了 Java 生态的标准化和互操作性
5. 从 Java 9 起采用半年发布周期，LTS 版本（如 11、17、21）适合生产环境
