## 1. 为什么用日志代替 System.out.println()

| System.out.println() 的问题 | 日志的优势 |
|---------------------------|-----------|
| 调试完需要删除 | 调整级别即可关闭 |
| 无时间、类名等信息 | 自动打印时间、类名、方法名 |
| 只能输出到控制台 | 可重定向到文件 |
| 无法按模块控制 | 可按包名控制输出级别 |

---

## 2. 基本用法

```java
import java.util.logging.Logger;

public class Hello {
    public static void main(String[] args) {
        Logger logger = Logger.getGlobal();
        logger.info("start process...");
        logger.warning("memory is running out...");
        logger.fine("ignored.");  // 默认不输出（级别低于 INFO）
        logger.severe("process will be terminated...");
    }
}
```

输出示例：

```
Mar 02, 2019 6:32:13 PM Hello main
INFO: start process...
Mar 02, 2019 6:32:13 PM Hello main
WARNING: memory is running out...
Mar 02, 2019 6:32:13 PM Hello main
SEVERE: process will be terminated...
```

---

## 3. 日志级别（从高到低）

| 级别 | 说明 |
|------|------|
| SEVERE | 严重错误 |
| WARNING | 警告 |
| **INFO** | **默认级别** |
| CONFIG | 配置信息 |
| FINE | 调试信息 |
| FINER | 更详细调试 |
| FINEST | 最详细调试 |

> 默认级别是 INFO，低于 INFO 的（CONFIG、FINE 等）不会输出。

---

## 4. JDK Logging 的局限

| 局限 | 说明 |
|------|------|
| 配置时机 | JVM 启动时读取，运行后无法修改 |
| 配置方式 | 需要 `-Djava.util.logging.config.file=xxx` 参数 |
| 使用不广泛 | 实际项目多用 SLF4J + Logback 等第三方框架 |

---

## 5. 关键总结

| 要点 | 说明 |
|------|------|
| 包 | `java.util.logging` |
| 获取 Logger | `Logger.getGlobal()` 或 `Logger.getLogger(类名)` |
| 级别控制 | 调整级别即可屏蔽/开启不同详细程度的日志 |
| 自动信息 | 时间、类名、方法名自动附加 |
| 实际项目 | JDK Logging 局限较多，后续学习更强大的日志框架 |
