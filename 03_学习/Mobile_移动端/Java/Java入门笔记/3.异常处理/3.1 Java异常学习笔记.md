## 1. 为什么需要异常机制

程序运行中不可避免会出错（用户输入错误、文件不存在、网络断开等）。

### 两种错误处理方式

| 方式 | 说明 | 缺点 |
|------|------|------|
| 错误码（int） | 约定返回值表示不同错误 | 处理麻烦，容易遗漏 |
| 异常机制 | 语言层面的异常处理 | Java 的方式，类型安全 |

---

## 2. 异常体系继承结构

```
                  Object
                    ▲
                Throwable
                 ▲     ▲
              Error   Exception
               ▲        ▲         ▲
  OutOfMemory  │  RuntimeException  IOException
  Error        │        ▲               ▲
               │   NullPointer      FileNotFound
               │   IndexOutOfBounds  ...
          StackOverflow
```

### 三大分类

| 类型 | 说明 | 是否必须捕获 |
|------|------|-------------|
| Error | 严重错误，程序无能为力 | ❌ 不需要 |
| RuntimeException | 程序逻辑 bug | ❌ 不强制（但建议处理） |
| Checked Exception | 可恢复的运行时错误 | ✅ 必须捕获或声明 |

### 常见异常归类

| Checked Exception | RuntimeException | Error |
|-------------------|------------------|-------|
| IOException | NullPointerException | OutOfMemoryError |
| FileNotFoundException | IndexOutOfBoundsException | StackOverflowError |
| UnsupportedEncodingException | IllegalArgumentException | NoClassDefFoundError |

---

## 3. 捕获异常：try...catch

```java
try {
    String s = processFile("C:\\test.txt");
} catch (FileNotFoundException e) {
    // 文件不存在
} catch (SecurityException e) {
    // 无权限
} catch (IOException e) {
    // IO 错误
} catch (Exception e) {
    // 其他错误
}
```

## 4. Checked Exception 的处理

方法声明可能抛出的异常用 `throws`：

```java
public byte[] getBytes(String charsetName) throws UnsupportedEncodingException {
    ...
}
```

调用方必须二选一：

### 选项一：捕获处理

```java
static byte[] toGBK(String s) {
    try {
        return s.getBytes("GBK");
    } catch (UnsupportedEncodingException e) {
        e.printStackTrace();
        return s.getBytes();
    }
}
```

### 选项二：继续向上声明

```java
static byte[] toGBK(String s) throws UnsupportedEncodingException {
    return s.getBytes("GBK");
}
```

> Checked Exception 必须在某一层被捕获，最终由编译器保证不会遗漏。

## 5. 最佳实践

| 做法 | 说明 |
|------|------|
| ❌ 捕获后什么都不做 | 吞掉异常，出了问题无法排查 |
| ✅ 至少记录异常 | `e.printStackTrace()` 或用日志框架记录 |
| ✅ 测试代码可用 throws | `main() throws Exception` 省去 try |
| ✅ 具体异常具体处理 | 不要只 catch Exception |

```java
// ❌ 不好
catch (Exception e) {
    // 什么也不干
}

// ✅ 至少记录
catch (Exception e) {
    e.printStackTrace();
}
```

---

## 6. 关键总结

| 要点 | 说明 |
|------|------|
| 异常是 class | 带类型信息，可在任何地方抛出，上层捕获 |
| Error | 严重错误，不需要捕获 |
| RuntimeException | 逻辑 bug，不强制捕获（修复代码） |
| Checked Exception | 必须 try...catch 或 throws 声明 |
| throws | 方法声明可能抛出的异常，编译器强制检查 |
| 不要吞异常 | 捕获后至少要记录 |
