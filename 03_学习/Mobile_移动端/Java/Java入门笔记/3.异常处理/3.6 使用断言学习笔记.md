## 1. 什么是断言

`assert` 关键字用于调试，验证程序中某个条件是否为 true：

```java
double x = Math.abs(-123.45);
assert x >= 0;                    // 条件为 false 时抛出 AssertionError
assert x >= 0 : "x must >= 0";   // 带消息的断言
```

---

## 2. 断言的特点

| 特点 | 说明 |
|------|------|
| 失败抛出 AssertionError | 程序直接退出，不可恢复 |
| 默认关闭 | JVM 默认忽略 assert 语句 |
| 需手动启用 | 加 `-ea` 参数才生效 |
| 仅用于调试 | 不能用于生产环境的错误处理 |

---

## 3. 启用断言

```bash
java -ea Main.java                         # 启用所有断言
java -ea:com.example.Main Main.java        # 只对指定类启用
java -ea:com.example... Main.java          # 对指定包启用（注意三个点）
```

---

## 4. 断言 vs 异常

| 场景 | 使用方式 |
|------|----------|
| 开发调试中验证假设 | `assert` |
| 可恢复的程序错误 | 抛出异常 |

```java
// ❌ 不应该用断言处理参数校验
void sort(int[] arr) {
    assert arr != null;
}

// ✅ 应该抛出异常
void sort(int[] arr) {
    if (arr == null) {
        throw new IllegalArgumentException("array cannot be null");
    }
}
```

> 断言在生产环境默认关闭，如果依赖断言做参数校验，上线后校验就消失了。

---

## 5. 关键总结

| 要点 | 说明 |
|------|------|
| 语法 | `assert 条件` 或 `assert 条件 : "消息"` |
| 默认关闭 | 必须 `-ea` 启用 |
| 用途 | 仅用于开发和测试阶段的调试 |
| 不能替代异常 | 可恢复错误用异常，不用断言 |
| 实际开发 | 很少使用，更好的方式是编写单元测试（JUnit） |
