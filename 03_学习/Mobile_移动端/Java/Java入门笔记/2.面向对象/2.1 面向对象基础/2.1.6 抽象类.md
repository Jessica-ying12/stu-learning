## 1. 为什么需要抽象类

父类的方法如果没有实际意义，但又不能去掉（去掉就失去多态），怎么办？

```java
// ❌ 方法没有实现体，编译错误
class Person {
    public void run();
}

// ❌ 去掉方法，失去多态
public void runTwice(Person p) {
    p.run();  // 编译错误：Person 没有 run()
}
```

**解决方案：** 声明为抽象方法 + 抽象类。

---

## 2. 抽象方法和抽象类

```java
abstract class Person {
    public abstract void run();  // 抽象方法：只有定义，没有实现
}
```

| 特点 | 说明 |
|------|------|
| `abstract` 方法 | 只有方法签名，没有方法体 `{}` |
| `abstract` 类 | 包含抽象方法的类必须声明为 abstract |
| 不能实例化 | `new Person()` 编译错误 |
| 设计用途 | 只能被继承，强迫子类实现抽象方法 |

---

## 3. 子类必须实现抽象方法

```java
abstract class Person {
    public abstract void run();
}

class Student extends Person {
    @Override
    public void run() {
        System.out.println("Student.run");
    }
}
```

| 情况 | 结果 |
|------|------|
| 子类实现了所有抽象方法 | 正常类，可以实例化 |
| 子类没有实现所有抽象方法 | 子类仍是抽象类，必须也加 `abstract` |

---

## 4. 抽象类可以包含非抽象方法

```java
abstract class Person {
    public abstract void run();  // 抽象方法，子类必须实现

    public String hello() {     // 普通方法，子类可以直接继承使用
        return "Hello";
    }
}
```

> 抽象类 = 部分实现的模板，既有规范（抽象方法）又有复用（普通方法）。

---

## 5. 面向抽象编程

```java
Person s = new Student();
Person t = new Teacher();
Person e = new Employee();

// 不关心具体子类型，统一调用
s.run();
t.run();
e.run();
```

### 面向抽象编程的本质

| 层次 | 职责 |
|------|------|
| 上层代码 | 定义规范（abstract class / 抽象方法） |
| 业务逻辑 | 不依赖子类就能正常编译 |
| 具体实现 | 由不同子类各自实现，调用者不关心细节 |

### 好处

- 新增子类时，上层代码无需修改
- 调用者只需知道"做什么"，不需知道"怎么做"
- 符合开闭原则（对扩展开放，对修改关闭）

---

## 6. 关键总结

| 要点 | 说明 |
|------|------|
| abstract 方法 | 只有定义没有实现，定义了子类必须实现的规范 |
| abstract 类 | 不能被实例化，只能被继承 |
| 子类义务 | 必须实现所有抽象方法，否则自身也是抽象类 |
| 面向抽象编程 | 引用高层类型，不关心具体实现 |
| 与接口的区别 | 抽象类可以有字段和普通方法；接口只能有抽象方法（后续学习） |
