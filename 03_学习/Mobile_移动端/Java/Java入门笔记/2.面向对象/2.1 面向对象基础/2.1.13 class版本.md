## 1. JDK 版本与 class 文件版本的对应关系

每个 JDK 版本编译输出的 class 文件有对应的版本号：

| JDK 版本 | class 版本号 |
|----------|-------------|
| Java 8 | 52 |
| Java 9 | 53 |
| Java 11 | 55 |
| Java 17 | 61 |
| Java 21 | 65 |
| Java 25 | 69 |

---

## 2. 兼容性规则

- **高版本 JVM 可以运行低版本 class**：Java 17 能运行 class 版本 55（Java 11 编译的）
- **低版本 JVM 不能运行高版本 class**：Java 11 不能运行 class 版本 61（Java 17 编译的）

运行不兼容的 class 会报错：

```
java.lang.UnsupportedClassVersionError: Xxx has been compiled by a more recent version...
```

> 类比 Word：Word 2016 能打开 Word 2013 的文件，反过来不行。

---

## 3. 指定编译输出版本

### 方式一：--release（推荐）

```bash
javac --release 11 Main.java
```

- 源码和输出都兼容 Java 11
- **会检查使用的 API 是否在目标版本中存在**

### 方式二：--source + --target

```bash
javac --source 9 --target 11 Main.java
```

- `--source 9`：按 Java 9 语法检查源码
- `--target 11`：输出 class 版本 55
- **不会检查 API 是否存在**，可能运行时出错

> 两种方式只能二选一，不能同时使用。

---

## 4. 潜在问题

用高版本 JDK 编译、指定低版本输出时，可能使用了高版本才有的 API：

```java
public class Hello {
    public static void hello(String name) {
        System.out.println("hello".indent(4));  // indent() 是 Java 12 新增的
    }
}
```

- 用 `--source 9 --target 11` 编译：编译通过（不检查 API）
- 用 Java 11 运行：`NoSuchMethodError`（String 没有 indent 方法）
- 用 `--release 11` 编译：**编译时就报错**（推荐）

---

## 5. 最佳实践

| 原则 | 说明 |
|------|------|
| 编译版本 = 运行版本 | 用 Java 11 运行就用 Java 11 编译 |
| 不指定参数时 | 默认 `--release 当前版本` |
| 多版本共存 | 通过 `JAVA_HOME` 环境变量切换当前 JDK |
| 优先用 --release | 比 --source + --target 更安全（会检查 API） |

---

## 6. 源码版本与语法特性

| 语法特性 | 最低源码版本 |
|----------|-------------|
| Lambda 表达式 | Java 8 |
| var 关键字 | Java 10 |
| switch 表达式 | Java 14（12/13 需 --enable-preview） |
| Text Blocks `"""` | Java 15（13/14 需 --enable-preview） |
| sealed class | Java 17（15/16 需 --enable-preview） |

---

## 7. 关键总结

| 要点 | 说明 |
|------|------|
| class 版本 | 每个 JDK 版本对应一个 class 文件版本号 |
| 向下兼容 | 高版本 JVM 能运行低版本 class，反过来不行 |
| UnsupportedClassVersionError | class 版本超出当前 JVM 能力 |
| --release | 推荐方式，同时限制语法和 API |
| 最佳实践 | 运行用什么版本，编译就用什么版本 |
