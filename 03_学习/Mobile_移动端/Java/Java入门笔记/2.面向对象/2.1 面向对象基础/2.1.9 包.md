## 1. 为什么需要包

解决类名冲突问题。不同包下可以有同名类：

- `ming.Person`（小明的 Person）
- `hong.Person`（小红的 Person）
- `java.util.Arrays`（JDK 的 Arrays）
- `mr.jun.Arrays`（小军的 Arrays）

> 完整类名 = 包名.类名。JVM 只看完整类名，包名不同就是不同的类。

---

## 2. 声明包

在 `.java` 文件**第一行**声明：

```java
package ming;  // 声明属于 ming 包

public class Person {
}
```

### 包的层级

- 用 `.` 分隔多层：`mr.jun`、`java.util`
- **包没有父子关系**：`java.util` 和 `java.util.zip` 是完全独立的两个包
- 不写包名 = 默认包，容易冲突，不推荐

---

## 3. 目录结构必须与包层次一致

```
src/
├── hong/
│   └── Person.java        // package hong;
├── ming/
│   └── Person.java        // package ming;
└── mr/
    └── jun/
        └── Arrays.java    // package mr.jun;
```

编译后的 `.class` 文件也遵循同样的目录结构。

---

## 4. import 导入

### 三种引用其他类的方式

```java
// 方式一：写完整类名（麻烦）
mr.jun.Arrays arrays = new mr.jun.Arrays();

// 方式二：import 导入后写简单类名（推荐）
import mr.jun.Arrays;
Arrays arrays = new Arrays();

// 方式三：通配符导入整个包（不推荐，看不清来源）
import mr.jun.*;
```

### 编译器自动导入

| 自动导入 | 说明 |
|----------|------|
| 当前包的所有 class | 同包内类无需 import |
| `java.lang.*` | String、System 等基础类 |

> 注意：`java.lang.reflect` 等子包仍需手动导入。

### 类名查找顺序

1. 完整类名 → 直接查找
2. 简单类名 → 当前包 → import 的包 → `java.lang` 包
3. 都找不到 → 编译报错

### 同名类冲突

只能 import 一个，另一个必须写完整类名。

## 5. 包作用域（默认访问级别）

不加任何修饰符的字段和方法，同一包内的类可以访问：

```java
package hello;
public class Person {
    void hello() { }  // 包作用域：同包可访问，外包不可
}

package hello;
public class Main {
    public static void main(String[] args) {
        new Person().hello();  // ✅ 同包，可以访问
    }
}
```

### 四种访问级别完整对比

| 修饰符 | 本类 | 同包 | 子类 | 外部 |
|--------|------|------|------|------|
| `private` | ✅ | ❌ | ❌ | ❌ |
| 默认（包作用域） | ✅ | ✅ | ❌ | ❌ |
| `protected` | ✅ | ✅ | ✅ | ❌ |
| `public` | ✅ | ✅ | ✅ | ✅ |

---

## 6. 包名命名最佳实践

使用倒置域名确保唯一性：

```
org.apache
org.apache.commons.log
com.liaoxuefeng.sample
```

### 避免与 JDK 类重名

- 不要用：`String`、`System`、`Runtime`
- 不要与常用类重名：`List`、`Format`、`BigInteger`

---

## 7. 编译和运行

```bash
# 目录结构
work/
├── bin/       # 存放编译后的 .class
└── src/       # 按包结构存放源码

# 编译（Linux/macOS）
$ javac -d ./bin src/**/*.java

# 运行
$ java -cp bin com.itranswarp.sample.Main
```

---

## 8. 关键总结

| 要点 | 说明 |
|------|------|
| package | 解决类名冲突，完整类名 = 包名.类名 |
| 目录结构 | 必须与包层次一致 |
| import | 导入后可用简单类名，避免用 `*` |
| 自动导入 | 当前包 + `java.lang.*` |
| 包作用域 | 无修饰符 = 同包可访问 |
| 命名规范 | 倒置域名，如 `com.example.project` |
| 包无父子关系 | `java.util` 和 `java.util.zip` 完全独立 |
