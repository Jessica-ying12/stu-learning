### 1. 可空类型 `?`

#### 概念
- **是什么**  
  在类型声明后添加 `?` 标记，表示该变量可以存储 `null` 值。例如 `int? a;` 表示 `a` 可以是整数，也可以是 `null`。
- **为什么需要**  
  在传统 Dart 中，所有类型都允许 `null`，导致空指针异常难以追踪。可空类型明确地将“可能为空”的变量与“永远不为空”的变量区分开，让编译器能够检查出潜在的空值访问。
- **解决什么问题**  
  解决在不确定变量是否为空时，因直接访问其成员而引发的运行时错误。

#### 原理
- **底层实现**  
  可空类型在类型系统中是原类型与 `Null` 类型的联合（`String?` 本质上是 `String|Null`）。编译器在静态分析阶段会跟踪变量的可空性。如果尝试对可空类型变量直接调用方法，会产生编译错误。
- **工作流程**  
  1. 声明变量时，若未指定 `?`，则默认为非空类型，必须初始化且不能为 `null`。  
  2. 声明为可空类型后，编译器允许其值为 `null`，但在访问成员前必须进行判空处理（如使用 `?.` 或 `!`）。  
  3. 运行时，可空类型变量实际存储的值要么是原类型对象，要么是 `null`。
- **关键技术点**  
  `int` 是 `int?` 的子类型，因为 `int` 的值集合是 `int?` 的子集（去掉了 `null`）。这种类型层次关系保证了可以将非空值赋给可空变量，反之则不行。

#### 使用方法
- **基本用法**  
  ```dart
  int? nullableInt;      // 默认值为 null
  String? name = 'Bard'; // 可以赋非空值
  name = null;           // 也可以赋 null
  ```
- **常见场景**  
  - 函数的可选参数、返回值可能为空。  
  - 解析 JSON 数据时，字段可能缺失。  
  - 需要表示“无值”状态（如查找不存在的元素）。
- **最佳实践**  
  - 尽量缩小可空类型的范围，只在确实需要 `null` 时才使用 `?`。  
  - 使用前进行判空，优先使用安全调用 `?.` 或空值合并 `??`，避免直接使用 `!`。

#### 注意事项
- **常见错误**  
  - 直接调用可空变量的成员：`int? a; print(a.isEven);` → 编译错误。  
  - 忘记初始化非空变量，却用可空类型来绕过检查，导致逻辑混乱。
- **性能问题**  
  可空类型本身无额外运行时开销，但频繁的判空可能增加少量代码体积。不过 Dart 编译器会优化。
- **兼容性**  
  - 从 Dart 2.12 开始，必须启用空安全。旧项目需通过迁移工具迁移。  
  - 混合模式（部分库支持空安全，部分不支持）可能产生问题，需确保所有依赖均支持空安全。

#### 代码示例
```dart
int? parseNumber(String? input) {
  if (input == null) return null; // 输入为 null 时返回 null
  return int.tryParse(input);
}

void main() {
  int? result = parseNumber('123');
  print(result?.isEven); // 安全调用，输出 false
  result = parseNumber(null);
  print(result?.isEven); // 输出 null
}
```


### 2. 非空类型

#### 概念
- **是什么**  
  在 Dart 空安全中，未加 `?` 修饰的类型都是非空类型，例如 `int`、`String`、`Foo`。这类变量**永远不能为 `null`**。
- **为什么需要**  
  确保绝大多数变量在正常情况下不会为空，将常见的“非空”假设变为语言强制的规则，减少空值检查代码，提升代码健壮性。
- **解决什么问题**  
  从根本上杜绝了因变量意外为 `null` 而导致的空指针异常。

#### 原理
- **底层实现**  
  类型系统在编译时确保所有非空类型变量在定义时被初始化，并且在后续所有赋值中都不能出现 `null`。编译器会进行数据流分析，检查可能的空值赋值。
- **工作流程**  
  1. 变量声明时未加 `?`，编译器要求必须赋初值（除非在构造函数中通过初始化列表或 `this.` 方式赋值）。  
  2. 后续所有赋值语句，右侧表达式必须保证为非空。  
  3. 调用非空变量的成员时，无需判空，编译器已保证其为非空。
- **关键技术点**  
  非空类型是顶层类型 `Object?` 的子类型。与可空类型之间的赋值规则：非空值可赋给可空变量，反之则不行（除非用断言 `!`）。

#### 使用方法
- **基本用法**  
  ```dart
  int a = 10;           // 正确，初始化为非空值
  String name;          // 错误：非空变量必须初始化
  final List<int> list; // 错误：final 变量必须在声明时初始化
  ```
- **常见场景**  
  - 几乎所有不需要表示“无值”的变量都应使用非空类型。  
  - 类的成员变量如果必须在构造完成后就存在，应使用非空类型并在构造函数中初始化。
- **最佳实践**  
  - 优先使用非空类型，只有在确实需要表示“无值”时才使用可空类型。  
  - 利用 `late` 关键字处理那些无法在声明时初始化，但一定会在使用前初始化的非空变量。

#### 注意事项
- **常见错误**  
  - 忘记初始化局部非空变量。  
  - 在可空上下文中错误地认为变量非空，导致编译错误。
- **性能问题**  
  无额外运行时开销，反而因去除了不必要的判空而可能提升性能。
- **兼容性**  
  所有新 Dart 代码默认使用空安全，非空类型是标准。旧代码迁移时需为可空变量添加 `?`，为延迟初始化添加 `late`。

#### 代码示例
```dart
class User {
  final String name; // 非空成员，必须在构造时初始化
  final int age;

  User(this.name, this.age); // 初始化

  void introduce() {
    print('I am $name, $age years old.'); // 直接使用，安全
  }
}

void main() {
  var user = User('Bard', 1);
  user.introduce();
  // user = null; // 错误：不能将 null 赋给非空变量
}
```


### 3. `late` 关键字

#### 概念
- **是什么**  
  `late` 修饰符用于非空变量，承诺该变量会在使用前被初始化，但允许在声明时暂不赋值。
- **为什么需要**  
  有些非空变量无法在声明时立即初始化（例如依赖注入、初始化方法调用后），但又不想将其改为可空类型（避免到处判空）。`late` 提供了一种延迟初始化的机制。
- **解决什么问题**  
  解决了“必须初始化”和“无法立即初始化”之间的矛盾，同时保持非空类型的便利。

#### 原理
- **底层实现**  
  `late` 变量在底层会被存储为可空类型，并附带一个标志位表示是否已赋值。首次访问时，如果标志位为未赋值，则会执行初始化表达式（若有）或抛出 `LateInitializationError`；如果已赋值，则直接返回值。
- **工作流程**  
  1. 声明 `late T x;`，编译器将其内部表示为一个可空 `T?` 并添加已赋值标志。  
  2. 当代码对 `x` 进行赋值时，设置标志为已赋值。  
  3. 当代码读取 `x` 时，检查标志；若未赋值则抛出异常，否则返回存储的值。
- **关键技术点**  
  - 如果 `late` 变量有初始化器（如 `late String name = getName();`），该初始化器是**惰性求值**的：只在第一次访问变量时才执行，且只执行一次。  
  - 延迟初始化可节省资源，特别是当初始化开销大且可能不需要使用时。

#### 使用方法
- **基本用法**  
  ```dart
  class Weather {
    late String description; // 延迟初始化

    void update(String data) {
      description = data;
    }

    void display() {
      print(description); // 如果 update 从未调用，会抛出 LateInitializationError
    }
  }

  // 惰性初始化示例
  late String heavy = computeHeavy(); // computeHeavy 在第一次访问 heavy 时调用
  ```
- **常见场景**  
  - 依赖注入（如 Flutter 的 `initState` 中初始化）。  
  - 循环依赖的对象。  
  - 开销大的计算，且可能不需要的场景（如缓存）。
- **最佳实践**  
  - 确保在使用 `late` 变量前确实赋值，否则会引发运行时错误。  
  - 对于顶层和静态变量，不需要加 `late`，它们本身已是惰性初始化。

#### 注意事项
- **常见错误**  
  - 忘记在使用前赋值，导致 `LateInitializationError`。  
  - 在多个线程/异步代码中，如果赋值前就有并发访问，可能引发竞态条件（但 Dart 单线程模型下较少见）。
- **性能问题**  
  - 每次访问 `late` 变量都有标志位检查开销，但通常可忽略。  
  - 惰性初始化可能延迟耗时操作，避免不必要的计算。
- **兼容性**  
  - `late` 是空安全的一部分，需要 Dart 2.12+。  
  - 迁移旧代码时，可将无法立即初始化的非空字段标记为 `late`，但需确保逻辑正确。

#### 代码示例
```dart
class DataFetcher {
  late String _cachedData; // 缓存数据

  Future<void> fetch() async {
    _cachedData = await fetchFromServer(); // 模拟异步获取
  }

  String getData() {
    return _cachedData; // 若 fetch 未完成，将抛出 LateInitializationError
  }
}

// 正确使用：确保 fetch 调用后再访问
void main() async {
  final fetcher = DataFetcher();
  await fetcher.fetch();
  print(fetcher.getData()); // 安全
}
```


### 4. `required` 关键字

#### 概念
- **是什么**  
  `required` 是一个修饰符，用于标记命名参数为必需参数。调用函数时必须为该参数传值。
- **为什么需要**  
  在空安全中，如果命名参数是非空类型，它要么有默认值，要么被标记为 `required`，否则默认值为 `null`，导致类型不匹配。
- **解决什么问题**  
  强制调用方提供必要的参数，避免因遗漏传参导致运行时错误。

#### 原理
- **底层实现**  
  `required` 是编译时检查。当函数定义中包含 `required` 参数时，编译器在调用点检查是否传入了对应的命名参数，若未传入则报编译错误。
- **工作流程**  
  1. 在函数或构造函数的参数列表中，对需要强制的命名参数添加 `required`。  
  2. 调用时，必须显式写出参数名并传递值，否则无法通过编译。  
  3. 运行时，该参数必然有值，且为非空（如果类型为非空）。
- **关键技术点**  
  - `required` 只能用于命名参数，不能用于位置参数。  
  - 可以与可空类型结合使用：`required int? x` 表示调用时必须传参，但值可以为 `null`。

#### 使用方法
- **基本用法**  
  ```dart
  void printInfo({required String name, required int age}) {
    print('$name is $age years old.');
  }

  // 构造函数中常用
  class Person {
    final String name;
    final int age;
    Person({required this.name, required this.age});
  }
  ```
- **常见场景**  
  - 类的构造函数，特别是需要强制初始化的非空字段。  
  - 函数有多个命名参数，其中一些必须提供。
- **最佳实践**  
  - 尽量使用 `required` 而非默认值，当参数没有合理默认值时。  
  - 对于可选参数，若不标记 `required`，可以设置默认值或保留可空类型。

#### 注意事项
- **常见错误**  
  - 忘记在调用时传递 `required` 参数，导致编译错误。  
  - 过度使用 `required`，导致调用方代码冗长。
- **性能问题**  
  无运行时开销，纯编译时特性。
- **兼容性**  
  - Dart 2.12+ 引入，替代了之前的 `@required` 注解（注解只产生警告，`required` 产生错误）。  
  - 迁移旧代码时，应将 `@required` 替换为 `required` 并确保调用点都传参。

#### 代码示例
```dart
class Point {
  final double x, y;
  Point({required this.x, required this.y}); // 必须提供 x 和 y
}

void main() {
  // var p = Point(x: 1); // 编译错误：缺少 required 参数 y
  var p = Point(x: 1, y: 2); // 正确
}
```


### 5. 空值合并运算符 `??`

#### 概念
- **是什么**  
  `??` 是一个二元运算符，如果左侧表达式不为 `null`，则返回左侧值；否则返回右侧值。
- **为什么需要**  
  简化常见的“如果值为空则使用默认值”的逻辑，避免冗长的 `if-else` 或三元表达式。
- **解决什么问题**  
  提供一种简洁、可读的方式处理可能为空的表达式，并提供备用值。

#### 原理
- **底层实现**  
  编译器会将 `a ?? b` 编译为类似 `((a) as dynamic) != null ? a : b` 的代码，但经过优化，避免重复计算 `a`。
- **工作流程**  
  1. 计算左侧表达式，获取结果。  
  2. 如果结果不为 `null`，整个表达式结果为该值。  
  3. 如果结果为 `null`，则计算右侧表达式，并以其结果作为整个表达式的结果。
- **关键技术点**  
  - 右侧表达式是惰性求值的：仅在左侧为 `null` 时才计算。  
  - 可以链式使用：`a ?? b ?? c`，返回第一个非空值。

#### 使用方法
- **基本用法**  
  ```dart
  String? name;
  String display = name ?? 'Guest'; // name 为 null，所以 display = 'Guest'
  name = 'Bard';
  display = name ?? 'Guest'; // display = 'Bard'
  ```
- **常见场景**  
  - 提供默认值。  
  - 从 Map 或可选链中提取值时设置后备。
- **最佳实践**  
  - 尽量让右侧表达式是常量或简单计算，避免副作用。  
  - 与 `?.` 结合使用非常方便：`user?.name ?? 'Anonymous'`。

#### 注意事项
- **常见错误**  
  - 混淆 `??` 和 `||`：`??` 只针对 `null`，而 `||` 针对 falsy 值（如 `false`、`0`）。  
  - 忘记右侧表达式类型必须可赋值给左侧表达式的类型，或类型不兼容导致编译错误。
- **性能问题**  
  极小，仅有一次 `null` 检查和可能的右侧表达式计算。
- **兼容性**  
  从 Dart 2.0 开始支持，空安全下更常用。

#### 代码示例
```dart
int? length;
print(length ?? 0); // 输出 0

Map<String, dynamic> json = {'name': 'Bard'};
String name = json['name'] as String? ?? 'Unknown';
print(name); // Bard

String? maybe;
String result = maybe ?? (throw Exception('Missing value')); // 可在右侧抛出异常
```


### 6. 空值赋值运算符 `??=`

#### 概念
- **是什么**  
  `??=` 是一个赋值运算符，仅当变量当前为 `null` 时，才将右侧的值赋给它。
- **为什么需要**  
  简化“如果变量为空则初始化”的常见模式。
- **解决什么问题**  
  避免显式判空后再赋值的冗长代码。

#### 原理
- **底层实现**  
  编译器将 `a ??= b` 编译为类似 `a = a ?? b` 的逻辑，但确保 `a` 只计算一次。
- **工作流程**  
  1. 读取左侧变量当前值。  
  2. 如果值为 `null`，则计算右侧表达式并将结果赋给左侧变量。  
  3. 如果值不为 `null`，则赋值操作被忽略。
- **关键技术点**  
  - 左侧必须是一个可赋值的变量（如普通变量、类的字段）。  
  - 右侧表达式仅在需要赋值时才计算。

#### 使用方法
- **基本用法**  
  ```dart
  int? height;
  height ??= 180; // height 为 null，所以赋值为 180
  print(height); // 180

  height ??= 200; // height 不为 null，赋值被忽略
  print(height); // 仍然是 180
  ```
- **常见场景**  
  - 懒加载初始化。  
  - 缓存填充：当缓存为空时从数据源加载。
- **最佳实践**  
  - 适用于那些希望保持首次赋值的场景。  
  - 可以配合 `??` 使用，但注意区分作用。

#### 注意事项
- **常见错误**  
  - 对非空变量使用 `??=` 没有意义，因为非空变量永远不会为 `null`，`??=` 不会生效（但语法允许，编译器可能提示）。  
  - 忘记 `??=` 会改变变量值，可能导致意外副作用。
- **性能问题**  
  无额外开销。
- **兼容性**  
  Dart 2.0 引入。

#### 代码示例
```dart
class Config {
  String? _cachedValue;

  String get value {
    _cachedValue ??= _loadFromDisk(); // 只在首次访问时加载
    return _cachedValue!;
  }

  String _loadFromDisk() => 'data';
}

void main() {
  var config = Config();
  print(config.value); // 触发加载
  print(config.value); // 使用缓存，不重复加载
}
```


### 7. 安全调用运算符 `?.`

#### 概念
- **是什么**  
  `?.` 允许在对象可能为 `null` 时安全地访问其成员。如果对象为 `null`，则调用返回 `null`；否则正常调用。
- **为什么需要**  
  避免在每次调用前都显式判断对象是否为 `null`，使代码更简洁。
- **解决什么问题**  
  将判空逻辑内嵌到访问操作中，减少样板代码。

#### 原理
- **底层实现**  
  编译器生成类似 `(x == null) ? null : x.member` 的代码，且只计算一次 `x`。
- **工作流程**  
  1. 计算左侧表达式，得到对象。  
  2. 如果对象为 `null`，整个表达式结果为 `null`（类型变为对应成员返回类型的可空版本）。  
  3. 如果对象非 `null`，则正常访问成员，表达式类型为成员返回类型（若成员返回非空，则整体仍可空）。
- **关键技术点**  
  - 可以连续使用：`obj?.prop?.method()?.toString()`。  
  - 与 `[]` 操作符结合：`list?.[index]`。

#### 使用方法
- **基本用法**  
  ```dart
  String? name;
  int? length = name?.length; // length 为 null
  name = 'Bard';
  length = name?.length; // length 为 4
  ```
- **常见场景**  
  - 访问可能为空的对象属性或方法。  
  - 链式调用时避免大量判空。
- **最佳实践**  
  - 优先使用 `?.` 而非 `!`，除非确定对象不为 `null`。  
  - 与 `??` 结合提供默认值：`user?.address?.city ?? 'Unknown'`。

#### 注意事项
- **常见错误**  
  - 忘记 `?.` 返回可空类型，直接赋值给非空变量会报错，需用 `??` 提供默认值。  
  - 在需要副作用的情况下，如果对象为 `null`，则不会调用方法，可能隐藏错误。
- **性能问题**  
  极小，相当于一次判空。
- **兼容性**  
  Dart 1.x 已有 `?.`，空安全下使用更频繁。

#### 代码示例
```dart
class Address {
  String city;
  Address(this.city);
}

class User {
  String name;
  Address? address;
  User(this.name, this.address);
}

void main() {
  User? user;
  print(user?.name); // null
  user = User('Bard', null);
  print(user.name); // Bard（user 非空，所以可直接访问）
  print(user.address?.city); // null
  user.address = Address('Shanghai');
  print(user.address?.city); // Shanghai
}
```


### 8. 空值断言运算符 `!`

#### 概念
- **是什么**  
  `!` 是一个后缀运算符，用于将可空类型表达式转换为对应的非空类型。如果表达式值为 `null`，则抛出运行时异常。
- **为什么需要**  
  当开发者确信某个可空值在特定上下文中不可能为 `null`，但编译器无法证明时，使用 `!` 来告诉编译器信任我们，从而通过类型检查。
- **解决什么问题**  
  作为可空世界到非空世界的“桥梁”，允许在确保安全的前提下简化代码。

#### 原理
- **底层实现**  
  编译器在 `expression!` 位置插入一个运行时检查：如果表达式为 `null`，则抛出 `TypeError`（实际是 `Null check operator used on a null value` 错误）；否则返回原值，类型提升为非空。
- **工作流程**  
  1. 计算左侧表达式，得到值 `v`。  
  2. 检查 `v == null`：如果为真，抛出异常；否则，将 `v` 作为非空类型返回。
- **关键技术点**  
  - 使用 `!` 后，表达式的静态类型变为非空，可以安全地访问成员。  
  - 若误用 `!`，程序会在运行时崩溃，因此应谨慎使用。

#### 使用方法
- **基本用法**  
  ```dart
  String? nullable = getMaybeString();
  int length = nullable!.length; // 如果 nullable 为 null，抛出异常
  ```
- **常见场景**  
  - 与 `late` 配合，在确保赋值后访问。  
  - 从已知不为 `null` 的可空变量中提取值，例如经过判空逻辑后。  
  - 从 Map 取值时确信键存在：`map[key]!`。  
  - 在测试或原型中临时使用，但正式代码应尽量避免。
- **最佳实践**  
  - 仅在确实能保证变量不为 `null` 时使用 `!`。  
  - 优先使用显式判空、`?.` 和 `??` 来安全处理。  
  - 当必须使用 `!` 时，添加注释说明为何此时不会为 `null`。

#### 注意事项
- **常见错误**  
  - 滥用 `!`，导致隐藏的空指针异常在运行时暴露。  
  - 在判空之后忘记使用 `!`，导致类型不匹配错误。  
  - 在异步操作中，变量可能在检查后被置为 `null`，导致 `!` 仍不安全。
- **性能问题**  
  添加了运行时检查，但开销极小。不过抛出异常的开销大，应避免。
- **兼容性**  
  空安全引入，需要 Dart 2.12+。在混合版本程序中，`!` 的行为保持不变。

#### 代码示例
```dart
void main() {
  String? maybe = 'hello';
  if (maybe != null) {
    // 在 if 分支内，Dart 会自动将 maybe 提升为非空，无需 ! 
    print(maybe.length); // 自动提升
  }

  // 从 Map 中取值（确信存在）
  Map<String, int> scores = {'Bard': 100};
  int bardsScore = scores['Bard']!; // 如果 'Bard' 不存在，则崩溃

  // 更安全的做法：
  int safeScore = scores['Bard'] ?? 0;
}
```


### 9. 类型提升

#### 概念
- **是什么**  
  类型提升是 Dart 编译器根据控制流自动将可空类型变量提升为非空类型的能力。当编译器能够证明变量不为 `null` 时，它允许你像使用非空类型一样访问该变量的成员。
- **为什么需要**  
  减少不必要的显式断言，使代码更简洁、更安全。
- **解决什么问题**  
  解决在判空后仍需手动转换的繁琐问题。

#### 原理
- **底层实现**  
  编译器进行数据流分析，追踪变量的赋值和判空检查。当某个分支路径确定变量不为 `null` 时，在该路径内变量的类型被提升为其对应的非空类型。
- **工作流程**  
  1. 声明可空变量。  
  2. 通过 `if (x != null)` 或类似条件检查后，在条件为真的代码块内，`x` 的类型被提升为非空。  
  3. 可以直接调用其方法，无需 `?.` 或 `!`。
- **关键技术点**  
  提升仅在变量不会被外部修改的局部范围内有效。如果变量可能被异步操作或闭包修改，提升可能失效。

#### 使用方法
- **基本用法**  
  ```dart
  int? maybeInt = 42;
  if (maybeInt != null) {
    // 此处 maybeInt 被提升为 int
    print(maybeInt.isEven); // 直接调用
  }
  ```
- **常见场景**  
  - 局部变量判空后使用。  
  - 使用 `||` 或 `&&` 组合条件后。
- **最佳实践**  
  - 尽量利用类型提升，减少 `!` 的使用。  
  - 注意提升的边界，避免在可能被修改的上下文中依赖提升。

#### 注意事项
- **常见错误**  
  - 在判空后修改变量值，提升可能失效。  
  - 在异步回调中使用判空后的变量，提升不跨异步边界。
- **性能问题**  
  无运行时开销，纯编译时特性。

#### 代码示例
```dart
void main() {
  String? name = getName();
  
  if (name != null) {
    // name 被提升为 String
    print('Name length: ${name.length}'); // 无需 name!.length
  }

  // 逻辑或条件中的提升
  if (name == null) return;
  // 此处 name 也被提升为 String
  print(name.length);
}
```


### 10. 健全空安全与不健全空安全

#### 概念
- **是什么**  
  - **健全空安全**：整个程序（包括所有依赖）都已迁移到空安全，编译器保证如果一个表达式的静态类型是非空，它在运行时绝不会为 `null`。  
  - **不健全空安全**：程序中混有空安全代码和未迁移的旧代码，`null` 可能从旧代码泄漏到空安全部分，运行时仍可能发生空引用错误。
- **为什么需要**  
  允许逐步迁移：大型项目无法一次性完成迁移，需要混合模式过渡。
- **解决什么问题**  
  健全性提供最强的安全保证和编译器优化；不健全性为增量迁移提供可行性。

#### 原理
- **底层实现**  
  Dart 工具支持两种运行模式：
  - 健全模式：所有库都已迁移，运行时强制执行健全保证。  
  - 不健全模式：检测到未迁移的库时自动切换，允许旧代码的 `null` 行为。
- **工作流程**  
  1. 如果入口库（含 `main`）已迁移，默认以健全模式运行。  
  2. 如果导入任何未迁移的库，工具会提示并以不健全模式运行，需添加 `--no-sound-null-safety` 标志。  
  3. 完全迁移后，自动获得健全性所有优势。
- **关键技术点**  
  - Dart 3 开始强制要求健全空安全，无法运行未迁移代码。  
  - 不健全模式下，仍可获得静态检查的好处，但运行时可能崩溃。

#### 使用方法
- **检查迁移状态**  
  ```bash
  dart pub outdated --mode=null-safety
  ```
- **运行混合程序**  
  ```bash
  dart --no-sound-null-safety run
  flutter run --no-sound-null-safety
  ```
- **逐步迁移策略**  
  从叶子库开始迁移，逐步扩大范围。

#### 注意事项
- **常见错误**  
  - 认为不健全模式完全安全，忽略运行时风险。  
  - 发布未完全迁移的包到 Dart 3 环境，导致用户无法使用。
- **性能问题**  
  不健全模式无法享受健全性带来的优化（如消除冗余判空）。
- **兼容性**  
  Dart 3 需要完全迁移，否则无法运行。

#### 代码示例
```dart
// lib.dart（未迁移）
// @dart=2.9
String maybe() {
  return null; // 允许返回 null
}

// main.dart（已迁移）
import 'lib.dart';

void main() {
  String value = maybe(); // 运行时可能抛出异常，因为 lib 未迁移
  print(value.length);
}
// 需以 --no-sound-null-safety 运行
```


### 11. 空安全迁移指南

#### 概念
- **是什么**  
  将未支持空安全的 Dart 代码升级到支持空安全的过程，包括更新依赖、修改代码、测试验证。
- **为什么需要**  
  - Dart 3 强制要求健全空安全。  
  - 获得更好的类型安全、性能和代码可维护性。
- **解决什么问题**  
  帮助开发者系统地将旧代码迁移到空安全世界。

#### 原理
- **迁移工具**  
  Dart SDK 2.12-2.19 包含 `dart migrate` 工具，可交互式分析代码并提供建议。
- **提示标记**  
  在代码中添加特殊注释指导迁移工具：
  - `/*?*/`：标记类型为可空  
  - `/*!*/`：标记表达式为非空断言  
  - `/*late*/`：标记延迟初始化  
  - `/*required*/`：标记必需参数
- **工作流程**  
  1. 等待所有依赖完成迁移。  
  2. 更新依赖到空安全版本：`dart pub upgrade --null-safety`。  
  3. 运行迁移工具或手动迁移。  
  4. 静态分析：`dart analyze`。  
  5. 测试：`dart test`。  
  6. 发布预发布版本。

#### 使用方法
- **检查依赖状态**  
  ```bash
  dart pub outdated --mode=null-safety
  ```
- **启动迁移工具**  
  ```bash
  dart migrate
  ```
- **手动迁移关键步骤**  
  - 在 `pubspec.yaml` 中设置 SDK 约束 `>=2.12.0`。  
  - 为可空变量添加 `?`。  
  - 为非空命名参数添加 `required` 或默认值。  
  - 为延迟初始化的非空字段添加 `late`。  
  - 用 `??`、`?.` 替换显式判空。

#### 注意事项
- **常见错误**  
  - 未等待依赖迁移就迁移代码，导致后续需要重改。  
  - 滥用 `!` 掩盖类型问题，引入运行时风险。  
  - 忘记更新测试代码，测试可能因 null 变化失败。
- **性能问题**  
  迁移后应重新测试性能，确保无退化。
- **兼容性**  
  - 发布迁移后的包时，应更新主版本号（因为存在破坏性变更）。  
  - 建议先发布预发布版本，收集反馈。

#### 代码示例
**迁移前（无空安全）**
```dart
class Person {
  String name;
  int age;
  
  Person(this.name, this.age);
  
  String describe() {
    if (age == null) {
      return 'Name: $name';
    }
    return 'Name: $name, Age: $age';
  }
}
```

**迁移后（空安全）**
```dart
class Person {
  String name;      // 非空
  int? age;         // 可空（因为可能为 null）
  
  Person(this.name, this.age); // age 可为 null
  
  String describe() {
    if (age == null) {
      return 'Name: $name';
    }
    return 'Name: $name, Age: $age';
  }
  
  // 或者使用类型提升
  String describeBetter() {
    if (age != null) {
      return 'Name: $name, Age: $age'; // age 被提升为 int
    }
    return 'Name: $name';
  }
}
```

**迁移工具提示标记示例**
```dart
// 原始代码
var ints = const <int>[0, null];
var zero = ints[0];

// 添加提示标记指导迁移
var zero = ints[0]/*!*/; // 告诉工具 zero 不可能为 null
```


## 总结

| 核心知识点 | 作用与讲解 | 注意事项 |
| :--- | :--- | :--- |
| **可空类型 `?`** | 声明变量可以存储 `null`，如 `int? x;` | 访问其属性前必须进行判空处理。 |
| **非空类型** | 默认类型，变量永远不能为 `null`，如 `int y;` | 声明时必须初始化或在构造函数中赋值。 |
| **`late`** | 用于延迟初始化非空变量，承诺在使用前赋值。 | 若使用前未赋值，会抛出 `LateInitializationError`。 |
| **`required`** | 标记命名参数为必需，调用时必须传参。 | 主要用于非空命名参数，确保其不会被遗漏。 |
| **`?.`** | 安全调用，如果对象为 `null`，则调用返回 `null`。 | 避免冗长的 `if (obj == null)` 判断。 |
| **`??`** | 提供默认值，当左侧表达式为 `null` 时，使用右侧值。 | 可以链式使用，如 `a ?? b ?? c`。 |
| **`??=`** | 当变量为 `null` 时，为其赋值。 | 常用于初始化可能为空的变量。 |
| **`!`** | 空值断言，告诉编译器“我确定它不为 `null`”。 | 使用需谨慎，错误的断言会导致运行时崩溃。 |
| **类型提升** | 编译器在判空后自动将可空类型视为非空。 | 提升仅在特定作用域有效。 |
| **健全性** | 完全迁移后，类型保证在运行时永不失效。 | Dart 3 强制要求健全空安全。 |
| **迁移指南** | 系统化将旧代码升级到空安全的流程。 | 依赖迁移顺序、工具使用、测试验证是关键。 |
