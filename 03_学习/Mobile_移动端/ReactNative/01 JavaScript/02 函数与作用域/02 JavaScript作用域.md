## 一、作用域基本概念
##### 概念
- **是什么**：作用域是当前的执行上下文，在该上下文中，值和表达式是“可见的”或可以被引用的。它定义了变量和函数的有效范围，决定了代码中哪些部分可以访问特定的变量。
- **为什么需要**：作用域的存在是为了隔离变量，避免命名冲突，保护代码安全，确保只有正确的代码部分可以访问特定变量。同时，它也是JavaScript引擎存储和管理变量的规则。
- **解决什么问题**：解决了全局命名空间污染问题，使不同作用域下的同名变量可以共存而不相互干扰；提供了封装性，隐藏内部实现细节。

##### 原理
- **底层实现**：在ECMAScript规范中，作用域是通过**词法环境**（Lexical Environment）实现的。每个执行上下文（如函数执行、全局执行）都有一个关联的词法环境，词法环境包含环境记录（记录变量和函数声明）和一个指向外部词法环境的引用（outer）。
- **工作流程**：当代码执行时，JavaScript引擎根据代码的结构创建相应的词法环境。变量和函数声明被添加到当前环境记录中。当需要查找变量时，引擎从当前环境记录开始，如果找不到则沿着outer引用向上查找，直到全局环境。
- **关键技术点**：词法作用域（静态作用域）、作用域链、环境记录。

##### 使用方法
- **基本用法**：通过函数、代码块（`{}`）、模块等结构自然地创建作用域。
- **常见场景**：
  - 全局作用域：在任何函数或代码块之外声明变量。
  - 函数作用域：在函数内部声明变量。
  - 块作用域：在`{}`内使用`let`或`const`声明变量。
- **最佳实践**：尽量将变量限制在最小的作用域内，避免全局变量；优先使用`const`和`let`而不是`var`。

##### 注意事项
- **常见错误**：误以为`for`循环中的`var`变量在循环外部不可访问（实际上由于函数作用域，它仍然可访问）；混淆块作用域和函数作用域。
- **性能问题**：作用域链查找变量会有轻微性能开销，但通常可忽略。频繁跨作用域访问变量可能影响性能，但现代引擎优化得很好。
- **兼容性**：块作用域（`let`/`const`）在ES6及以上环境支持，旧环境需转译。

##### 代码示例
```javascript
// 全局作用域
var globalVar = "global";

function outer() {
    // 函数作用域
    var outerVar = "outer";
    
    if (true) {
        // 块作用域
        let blockVar = "block";
        console.log(globalVar); // 可访问
        console.log(outerVar);  // 可访问
    }
    // console.log(blockVar); // 报错：blockVar未定义
}
outer();
```

## 二、全局作用域
##### 概念
- **是什么**：在代码的任何函数或代码块（`{}`）之外声明的变量，就处于全局作用域下。
- **为什么需要**：全局作用域提供了程序运行时的根环境，所有模块和函数都可以共享全局变量，便于跨函数通信。
- **解决什么问题**：解决了代码不同部分需要共享数据的场景。但过度使用会导致命名冲突和代码耦合。

##### 原理
- **底层实现**：全局作用域对应全局词法环境，其外部引用（outer）为`null`。在浏览器中，全局环境的环境记录与`window`对象关联（对于`var`和函数声明）。
- **工作流程**：当脚本加载时，全局执行上下文被创建，全局变量和函数被添加到全局环境记录中。任何不在局部作用域的变量查找最终都会到达全局环境。
- **关键技术点**：全局对象（浏览器中的`window`，Node.js中的`global`），`var`声明和`let/const`声明在全局对象上的不同表现。

##### 使用方法
- **基本用法**：直接在脚本顶层声明变量（不使用任何函数或块包裹）。
- **常见场景**：
  - 定义常量或配置，供整个应用使用。
  - 定义全局函数或工具库。
  - 作为模块的命名空间（如`var MyApp = {};`）。
- **最佳实践**：尽量减少全局变量，使用模块化（ES6模块）代替；如果必须使用，用一个唯一的全局对象作为命名空间。

##### 注意事项
- **常见错误**：意外创建全局变量（如未声明的变量赋值`x = 1;`，在非严格模式下会成为全局变量）；全局变量污染导致命名冲突。
- **性能问题**：频繁访问全局变量比访问局部变量稍慢，因为作用域链更长。
- **兼容性**：在所有JavaScript环境中都存在。

##### 代码示例
```javascript
// 全局作用域示例
var globalVar = "I am global";
let globalLet = "I am also global";

function test() {
    console.log(globalVar); // 可访问
    globalVar = "modified";
}

test();
console.log(globalVar); // "modified"

// 未声明变量（非严格模式）会成为全局变量
function bad() {
    mistake = "oops"; // 漏写var/let/const
}
bad();
console.log(mistake); // "oops"（但严格模式下报错）
```

## 三、函数作用域
##### 概念
- **是什么**：在函数内部声明的变量，就处于函数作用域内。这些变量在函数外部无法直接访问。
- **为什么需要**：函数作用域提供了封装性，可以将函数内部实现细节隐藏起来，只暴露必要的接口。
- **解决什么问题**：解决了变量污染问题，使函数内部的变量不会影响外部代码；支持模块化设计。

##### 原理
- **底层实现**：每次调用函数时，都会创建一个新的函数执行上下文，其中包含一个词法环境。该环境的outer引用指向函数定义时的外部环境。函数内部用`var`、`let`、`const`声明的变量都存储在这个环境的记录中。
- **工作流程**：函数执行时，变量声明被添加到当前环境记录。当函数执行结束，如果该函数没有被闭包引用，其环境可能被销毁。函数作用域是静态的，由函数定义位置决定。
- **关键技术点**：函数执行上下文、环境记录、作用域链。

##### 使用方法
- **基本用法**：在函数内部使用`var`、`let`或`const`声明变量。
- **常见场景**：
  - 定义局部变量，防止外部访问。
  - 实现模块模式（结合闭包）。
  - 在函数内部封装私有数据。
- **最佳实践**：始终在函数内部使用声明关键字（`var`/`let`/`const`），避免意外创建全局变量。

##### 注意事项
- **常见错误**：忘记使用关键字导致意外全局变量；在函数外部访问函数内部变量（直接访问会报错）。
- **性能问题**：无显著性能问题。
- **兼容性**：所有版本都支持。

##### 代码示例
```javascript
function myFunc() {
    var localVar = "I'm local";
    let alsoLocal = "me too";
    console.log(localVar); // 可访问
}
myFunc();
// console.log(localVar); // 报错：localVar未定义

// 函数作用域的嵌套
function outer() {
    var outerVar = "outer";
    function inner() {
        var innerVar = "inner";
        console.log(outerVar); // 可访问
    }
    inner();
    // console.log(innerVar); // 报错：innerVar未定义
}
outer();
```

## 四、块作用域
##### 概念
- **是什么**：由一对花括号`{}`包裹的代码块所创建的作用域。在ES6之前，JavaScript没有块作用域；ES6引入`let`和`const`后，块作用域得以实现。
- **为什么需要**：块作用域允许将变量的生命周期限制在代码块（如`if`、`for`、`while`）内部，避免变量泄漏到外部，提高代码的可预测性。
- **解决什么问题**：解决了`var`导致的变量提升和循环计数器泄漏的问题，使代码更符合其他类C语言的习惯。

##### 原理
- **底层实现**：块作用域也是通过词法环境实现的。当进入一个块（如`if`或`for`）时，会创建一个新的词法环境，其outer引用指向外部环境。用`let`和`const`声明的变量被添加到这个块环境的记录中，块结束后该环境可能被销毁。
- **工作流程**：执行到块时创建块级词法环境，块内声明的`let`/`const`变量被绑定到该环境，但存在临时死区（TDZ）。块执行完毕后，如果没有闭包引用，块环境被回收。
- **关键技术点**：临时死区（TDZ）、块级词法环境。

##### 使用方法
- **基本用法**：在`{}`内使用`let`或`const`声明变量。
- **常见场景**：
  - `for`循环中计数器变量，避免循环后仍可访问。
  - `if`语句内部分支局部变量。
  - `switch`语句中的临时变量。
- **最佳实践**：优先使用`let`和`const`而不是`var`，充分利用块作用域。

##### 注意事项
- **常见错误**：误以为`var`在块内会受块作用域限制；忽略TDZ导致在声明前使用变量。
- **性能问题**：无显著性能问题。
- **兼容性**：ES6及以上环境支持，旧环境需转译。

##### 代码示例
```javascript
// 块作用域示例
{
    let blockVar = "inside block";
    const BLOCK_CONST = "constant";
    console.log(blockVar); // 可访问
}
// console.log(blockVar); // 报错：blockVar未定义

// for循环中的应用
for (let i = 0; i < 3; i++) {
    // i只在循环内有效
}
// console.log(i); // 报错

// TDZ示例
{
    // console.log(x); // 报错：Cannot access before initialization
    let x = 5;
}
```

## 五、模块作用域
##### 概念
- **是什么**：ES6模块中，每个模块都有自己的作用域。模块顶层声明的变量默认是模块私有的，不会自动成为全局变量。
- **为什么需要**：模块作用域提供了更高级的封装，使JavaScript能够支持大型应用的模块化开发，避免全局污染，并明确依赖关系。
- **解决什么问题**：解决了全局作用域滥用导致的冲突和依赖管理困难，实现了模块之间的隔离和显式导入/导出。

##### 原理
- **底层实现**：模块被加载时，会创建一个模块环境记录，该环境记录与全局环境分离。模块中的顶层声明（如变量、函数、类）被绑定到模块环境。通过`export`导出时，导出的是对环境记录的绑定；`import`则导入这些绑定。
- **工作流程**：模块代码在严格模式下执行。模块的作用域链顶层是模块环境，其outer引用指向全局环境（但模块中顶层`this`是`undefined`）。导入的变量在模块环境中作为只读绑定存在。
- **关键技术点**：模块环境记录、导入导出绑定、静态模块结构。

##### 使用方法
- **基本用法**：使用`<script type="module">`或在打包工具中使用`.mjs`文件。通过`export`导出，`import`导入。
- **常见场景**：
  - 将代码拆分成独立文件，每个文件一个模块。
  - 封装工具库，只暴露公共API。
  - 管理依赖，避免全局冲突。
- **最佳实践**：每个模块只做一件事，合理导出；避免循环依赖。

##### 注意事项
- **常见错误**：忘记`export`导致其他模块无法访问；在模块中意外修改导入的变量（导入的变量是只读的）。
- **性能问题**：模块加载是异步的，可能影响初始加载时间，但现代打包工具可优化。
- **兼容性**：ES6模块在现代浏览器和Node.js中支持，旧环境需使用打包工具（如Webpack）。

##### 代码示例
```javascript
// module.js
export const publicValue = 42;
function privateFunction() {
    return "private";
}
export function publicFunction() {
    return privateFunction();
}

// main.js
import { publicValue, publicFunction } from './module.js';
console.log(publicValue); // 42
console.log(publicFunction()); // "private"
// console.log(privateFunction()); // 报错：privateFunction未定义
```

## 六、作用域链
##### 概念
- **是什么**：作用域链是当代码在一个环境中执行时，由当前环境到外部环境的变量对象（或环境记录）组成的链式结构。它保证了变量和函数的有序访问。
- **为什么需要**：作用域链是实现词法作用域的关键机制，它定义了变量查找的路径，使得内部函数可以访问外部函数的变量。
- **解决什么问题**：解决了嵌套作用域中变量的查找规则问题，使得代码在访问变量时能够按照定义时的结构逐级向上查找。

##### 原理
- **底层实现**：每个执行上下文都有一个词法环境，词法环境包含一个指向外部词法环境的引用（`[[OuterEnv]]`）。当需要解析一个标识符时，从当前词法环境开始，沿着`[[OuterEnv]]`链查找，直到找到该标识符或到达`null`（全局环境的外部引用为`null`）。
- **工作流程**：函数定义时保存了当前的作用域链；函数调用时，将当前作用域链与函数创建时的作用域链结合，形成完整的作用域链。变量查找顺序：当前环境 → 外部环境 → ... → 全局环境。
- **关键技术点**：词法环境、外部引用、标识符解析。

##### 使用方法
- **基本用法**：通过嵌套函数自然形成作用域链，变量查找自动沿链进行。
- **常见场景**：
  - 内部函数访问外部函数的变量。
  - 闭包中保留对外部变量的引用。
  - 理解变量查找的优先级。
- **最佳实践**：合理设计嵌套层次，避免过深的作用域链；理解变量屏蔽（内部变量屏蔽外部同名变量）。

##### 注意事项
- **常见错误**：误以为作用域链是动态的（由调用位置决定），实际上是静态的（由定义位置决定）；混淆作用域链和原型链。
- **性能问题**：过深的作用域链可能增加查找时间，但现代引擎优化良好；频繁跨多层访问可能稍慢。
- **兼容性**：所有版本都遵循此机制。

##### 代码示例
```javascript
var x = 10;

function foo() {
    var y = 20;
    function bar() {
        var z = 30;
        console.log(x + y + z); // 沿作用域链查找：z在bar，y在foo，x在全局
    }
    bar();
}
foo(); // 60

// 变量屏蔽示例
var name = "Global";
function outer() {
    var name = "Outer";
    function inner() {
        var name = "Inner";
        console.log(name); // "Inner"（屏蔽外部）
    }
    inner();
    console.log(name); // "Outer"
}
outer();
console.log(name); // "Global"
```

## 七、词法作用域（静态作用域）
##### 概念
- **是什么**：词法作用域是指变量的作用域在代码编写（定义）时就已经确定，而不是在运行时动态决定。JavaScript采用的就是词法作用域。
- **为什么需要**：词法作用域使得代码的行为更容易预测，因为函数的作用域基于其定义位置，而不依赖于调用位置。
- **解决什么问题**：解决了作用域动态绑定带来的混乱，提高了代码的可读性和可靠性。

##### 原理
- **底层实现**：函数对象在创建时，会保存当前词法环境的引用（称为`[[Environment]]`）。当函数被调用时，新创建的词法环境的`[[OuterEnv]]`就指向这个保存的环境，从而实现了词法作用域。
- **工作流程**：函数定义时捕获当前作用域链；函数执行时，无论在哪里调用，其作用域链都基于捕获时的链。
- **关键技术点**：函数对象的`[[Environment]]`内部槽，闭包的实现基础。

##### 使用方法
- **基本用法**：无需显式操作，JavaScript默认采用。
- **常见场景**：
  - 理解函数内部变量查找为何不依赖调用上下文。
  - 闭包的形成。
- **最佳实践**：基于词法作用域设计代码，避免依赖动态特性（如`eval`、`with`）。

##### 注意事项
- **常见错误**：混淆`this`绑定（动态）和作用域（静态）；误以为函数内部变量由调用者决定。
- **性能问题**：词法作用域有利于引擎优化，因为作用域结构静态可知。
- **兼容性**：所有版本都支持。

##### 代码示例
```javascript
function foo() {
    console.log(a);
}

function bar() {
    var a = 3;
    foo();
}

var a = 2;
bar(); // 输出2，而不是3。因为foo定义时捕获的a是全局的2。
```

## 八、变量提升
##### 概念
- **是什么**：变量提升是JavaScript中一种机制，在代码执行前，JavaScript解释器会将变量和函数的声明“移动”到其所在作用域的顶部。实际实现中，这是编译阶段将声明放入内存的结果。
- **为什么需要**：提升允许函数和变量在声明之前使用，这在某些情况下提供了灵活性（如递归、相互递归）。
- **解决什么问题**：解决了函数声明必须先定义后使用的问题，使得代码组织更自由。

##### 原理
- **底层实现**：在创建执行上下文时，有两个阶段：创建阶段（编译阶段）和执行阶段。创建阶段，引擎扫描所有变量和函数声明，将变量和函数添加到当前词法环境或变量环境中，并初始化（函数声明直接赋值，`var`变量初始化为`undefined`，`let`/`const`变量保持未初始化）。
- **工作流程**：
  - 函数声明：整个函数体被提升，可提前调用。
  - `var`声明：声明被提升，但初始化（赋值）留在原地，因此提前访问值为`undefined`。
  - `let`/`const`声明：声明被提升，但未初始化，进入临时死区（TDZ），提前访问报错。
- **关键技术点**：执行上下文创建阶段、变量环境、词法环境、临时死区。

##### 使用方法
- **基本用法**：理解提升规则，避免依赖提升编写代码。
- **常见场景**：
  - 利用函数提升在文件底部定义函数，顶部调用。
  - 注意`var`变量提升可能导致意外结果。
- **最佳实践**：始终在使用变量和函数之前声明它们，避免依赖提升；优先使用`let`/`const`以提前发现错误。

##### 注意事项
- **常见错误**：误以为`let`/`const`不提升；在`var`变量声明前使用导致`undefined`而非报错；混淆函数声明和函数表达式的提升差异。
- **性能问题**：无。
- **兼容性**：所有版本支持（`let`/`const`提升但TDZ是ES6特性）。

##### 代码示例
```javascript
// 函数提升
console.log(add(2, 3)); // 5
function add(a, b) {
    return a + b;
}

// var提升
console.log(x); // undefined（而非报错）
var x = 10;

// let/const提升（TDZ）
// console.log(y); // 报错：Cannot access before initialization
let y = 20;

// 函数表达式不提升
// console.log(sub(5, 2)); // 报错：sub is not a function
var sub = function(a, b) {
    return a - b;
};
```

## 九、临时死区（TDZ）
##### 概念
- **是什么**：临时死区（Temporal Dead Zone）是指从代码块开始到变量声明完成之间的区域，在此期间无法访问该变量。适用于`let`和`const`声明的变量。
- **为什么需要**：TDZ是为了强制开发者在声明变量之后才能使用，避免因提升导致的未定义行为，使代码更安全、更可预测。
- **解决什么问题**：解决了`var`变量提升导致的诡异行为（如访问到`undefined`而非报错），确保变量在使用前已被正确初始化。

##### 原理
- **底层实现**：在词法环境中，`let`和`const`声明的变量在创建阶段被添加到环境记录中，但被标记为“未初始化”。当代码执行到声明语句时，变量才被初始化为指定值（`const`必须初始化）。在执行到声明语句之前访问变量，引擎会抛出`ReferenceError`。
- **工作流程**：进入块作用域 → 创建块级词法环境，`let`/`const`变量被记录但未初始化（进入TDZ） → 执行代码直到变量声明语句 → 变量被初始化，离开TDZ → 后续可正常访问。
- **关键技术点**：未初始化状态、声明语句的执行时机。

##### 使用方法
- **基本用法**：无需显式操作，了解即可。编写代码时应确保在声明后使用`let`/`const`变量。
- **常见场景**：
  - 在块内声明`let`变量前访问它会触发TDZ。
  - 在函数参数默认值中也可能出现TDZ（当默认值引用后面的参数时）。
- **最佳实践**：始终在作用域顶部声明变量，避免TDZ陷阱。

##### 注意事项
- **常见错误**：在声明前使用`let`/`const`变量；在`typeof`操作符应用于TDZ中的变量也会抛出`ReferenceError`（不同于`var`，`typeof`未声明变量返回`undefined`）。
- **性能问题**：无。
- **兼容性**：ES6及以上。

##### 代码示例
```javascript
{
    // TDZ开始
    // console.log(a); // ReferenceError
    // typeof a; // 也报错！不同于var
    
    let a = 10; // TDZ结束
    console.log(a); // 10
}

// 参数默认值中的TDZ
function test(x = y, y = 2) {
    // 这里x默认值试图访问y，但y此时还在TDZ中
    return [x, y];
}
// test(); // 报错：Cannot access before initialization

// 正确方式：先声明后使用
function test2(x = 2, y = x) {
    return [x, y];
}
console.log(test2()); // [2, 2]
```

## 十、闭包
##### 概念
- **是什么**：闭包是指有权访问另一个函数作用域中的变量的函数。或者说，闭包是一个函数及其词法环境的组合。
- **为什么需要**：闭包允许函数访问其定义时的外部变量，即使外部函数已经执行完毕。它实现了数据的私有化、记忆化、函数工厂等高级编程模式。
- **解决什么问题**：解决了在函数外部访问函数内部变量的需求；提供了一种封装数据的方法；是实现许多函数式编程特性的基础。

##### 原理
- **底层实现**：当一个函数被定义时，它会保存当前词法环境的引用（`[[Environment]]`）。当这个函数被调用时，即使其外部函数已经返回，它依然可以通过这个引用访问外部函数的变量对象，因为外部函数的变量对象仍然被闭包引用，不会被垃圾回收。
- **工作流程**：
  1. 外部函数定义，创建外部词法环境。
  2. 内部函数定义，捕获外部词法环境（保存`[[Environment]]`）。
  3. 外部函数返回内部函数（或将其传递给其他地方）。
  4. 外部函数执行完毕，通常其词法环境应被销毁，但由于内部函数的`[[Environment]]`仍然引用它，因此它继续存在。
  5. 调用内部函数时，其词法环境的`[[OuterEnv]]`指向保存的外部环境，因此可以访问外部变量。
- **关键技术点**：函数对象的`[[Environment]]`、垃圾回收、活动对象。

##### 使用方法
- **基本用法**：在一个函数内部定义另一个函数，并返回该函数或将其作为回调传递。
- **常见场景**：
  - 创建私有变量（模块模式）。
  - 实现柯里化和函数工厂。
  - 事件处理和回调中保留状态。
  - 循环中保存每次迭代的值（结合立即执行函数或`let`）。
- **最佳实践**：合理使用闭包，避免内存泄漏（不再需要的闭包要及时解除引用）。

##### 注意事项
- **常见错误**：循环中创建闭包导致共享同一个变量；闭包无意中引用大对象导致内存无法释放。
- **性能问题**：闭包可能导致外部函数的变量无法被垃圾回收，增加内存占用；频繁创建闭包可能影响性能。
- **兼容性**：所有版本支持。

##### 代码示例
```javascript
// 基本闭包
function makeCounter() {
    let count = 0;
    return function() {
        count++;
        return count;
    };
}

const counter = makeCounter();
console.log(counter()); // 1
console.log(counter()); // 2

// 私有变量
function createPerson(name) {
    let age = 0;
    return {
        getName: () => name,
        getAge: () => age,
        setAge: (newAge) => { age = newAge; }
    };
}
const person = createPerson('Alice');
console.log(person.getName()); // Alice
person.setAge(25);
console.log(person.getAge()); // 25

// 循环陷阱与解决
// 错误：所有函数共享同一个i
var funcs = [];
for (var i = 0; i < 3; i++) {
    funcs[i] = function() { console.log(i); };
}
funcs[0](); // 3

// 正确：使用立即执行函数捕获每次的i
for (var i = 0; i < 3; i++) {
    funcs[i] = (function(x) {
        return function() { console.log(x); };
    })(i);
}
funcs[0](); // 0

// 正确：使用let
for (let i = 0; i < 3; i++) {
    funcs[i] = function() { console.log(i); };
}
funcs[0](); // 0
```

## 十一、高阶函数
##### 概念
- **是什么**：高阶函数是指至少满足以下条件之一的函数：接受一个或多个函数作为参数；返回一个函数作为结果。
- **为什么需要**：高阶函数是函数式编程的核心，它允许对函数进行抽象、组合和增强，提高代码的复用性和表达力。
- **解决什么问题**：解决了将行为作为参数传递的问题，支持回调、函数组合、装饰器等模式。

##### 原理
- **底层实现**：在JavaScript中，函数是一等公民，可以作为值传递。高阶函数利用了这一特性，通过参数接收函数，或者通过闭包返回新函数。
- **工作流程**：
  - 作为参数：在函数内部调用传入的函数。
  - 作为返回值：在函数内部定义一个新函数并返回，通常结合闭包保留状态。
- **关键技术点**：一等函数、闭包、函数组合。

##### 使用方法
- **基本用法**：编写函数，参数中包含函数类型，或者返回一个新函数。
- **常见场景**：
  - 数组方法（`map`、`filter`、`reduce`）。
  - 事件监听和回调。
  - 函数节流/防抖。
  - 函数柯里化和部分应用。
- **最佳实践**：保持高阶函数的通用性，避免副作用；合理命名，清晰表达意图。

##### 注意事项
- **常见错误**：忘记传递参数导致直接执行函数而非传递引用；回调地狱（可使用Promise/async解决）。
- **性能问题**：过度使用高阶函数可能增加调用栈和内存，但通常可接受。
- **兼容性**：所有版本支持。

##### 代码示例
```javascript
// 接受函数作为参数
function map(arr, fn) {
    const result = [];
    for (let i = 0; i < arr.length; i++) {
        result.push(fn(arr[i], i, arr));
    }
    return result;
}
const numbers = [1, 2, 3];
const doubled = map(numbers, x => x * 2);
console.log(doubled); // [2, 4, 6]

// 返回函数作为结果
function multiplyBy(factor) {
    return function(number) {
        return number * factor;
    };
}
const double = multiplyBy(2);
console.log(double(5)); // 10

// 内置高阶函数
const evens = numbers.filter(x => x % 2 === 0);
const sum = numbers.reduce((acc, x) => acc + x, 0);
console.log(evens, sum); // [2] 6
```

## 十二、最佳实践与注意事项
##### 概念
- **是什么**：总结作用域相关的最佳实践和常见注意事项，帮助开发者编写健壮、高效的代码。
- **为什么需要**：避免常见的错误，提高代码质量和可维护性。
- **解决什么问题**：总结了前面各知识点的应用建议，形成统一的编码规范。

##### 原理
- **底层实现**：基于JavaScript引擎的行为和语言规范。
- **工作流程**：在编码时遵循建议，利用引擎优化特性。
- **关键技术点**：变量声明、作用域设计、内存管理。

##### 使用方法
- **基本用法**：遵循以下建议：
  - 尽量使用`const`，必要时用`let`，避免`var`。
  - 将变量声明在最小作用域内。
  - 避免全局变量，使用模块化。
  - 使用立即执行函数或块作用域创建临时私有空间。
  - 避免创建不必要的闭包，及时解除引用。
  - 理解提升和TDZ，始终先声明后使用。
  - 使用严格模式（`'use strict'`）避免意外全局变量。
- **常见场景**：日常编码中应用上述建议。
- **最佳实践**：结合团队规范，使用ESLint等工具检查。

##### 注意事项
- **常见错误**：忘记声明关键字导致全局变量；循环中闭包陷阱；过度依赖闭包导致内存泄漏；在TDZ中使用变量。
- **性能问题**：避免在热路径中创建大量闭包；合理使用变量缓存。
- **兼容性**：针对旧环境使用转译工具。
