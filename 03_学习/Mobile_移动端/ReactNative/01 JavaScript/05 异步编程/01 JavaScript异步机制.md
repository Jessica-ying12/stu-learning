## 一、核心概念

### 1. 同步 vs 异步

#### 概念

- **是什么**  
  同步和异步是描述程序任务之间**消息通信机制**的术语，关注的是**调用方如何获取结果**。  
  - **同步**：任务发起调用后，调用方必须主动等待结果返回，在结果返回之前无法执行后续代码。  
  - **异步**：任务发起调用后，调用方可以立即继续执行后续代码，当任务完成时通过状态变更、回调函数或事件等方式通知调用方。

- **为什么需要**  
  JavaScript是单线程语言，如果所有操作都是同步的，遇到耗时任务（如网络请求、定时器、文件I/O）就会阻塞线程，导致页面无响应。异步机制允许主线程在等待耗时操作的同时继续处理其他任务，保持应用的流畅性。

- **解决什么问题**  
  解决单线程环境下**I/O等待阻塞**问题，提高CPU利用率，实现非阻塞并发。

#### 原理

- **底层实现**  
  JavaScript的异步依赖于**事件循环（Event Loop）**和**任务队列**。当遇到异步操作（如setTimeout、Promise、Ajax）时，将其回调函数或任务添加到相应的任务队列中，主线程继续执行后续同步代码。待同步代码执行完毕且调用栈清空后，事件循环会从任务队列中取出任务执行。

- **工作流程**  
  1. 执行同步代码（放入调用栈）。  
  2. 遇到异步API，将其交给浏览器/Node.js的相应线程处理（如定时器线程、网络线程），同时将回调函数包装成任务放入任务队列。  
  3. 同步代码执行完毕，调用栈清空。  
  4. 事件循环检查微任务队列并执行所有微任务。  
  5. 从宏任务队列中取出一个宏任务执行。  
  6. 重复4、5步。

- **关键技术点**  
  - 事件循环机制  
  - 宏任务与微任务的区分  
  - 回调函数、Promise、async/await等异步编程模式

#### 使用方法

- **基本用法**  
  ```javascript
  // 同步代码
  console.log('start');
  
  // 异步（定时器）
  setTimeout(() => {
    console.log('timeout');
  }, 1000);
  
  // 异步（Promise）
  Promise.resolve().then(() => {
    console.log('promise');
  });
  
  console.log('end');
  // 输出顺序：start, end, promise, timeout
  ```

- **常见场景**  
  - 网络请求（Ajax、fetch）  
  - 定时器（setTimeout、setInterval）  
  - 文件读写（Node.js）  
  - 用户交互事件（click、scroll等）  
  - DOM渲染后的回调

- **最佳实践**  
  - 优先使用Promise和async/await代替传统回调，避免“回调地狱”。  
  - 合理拆分异步任务，避免长任务阻塞事件循环。  
  - 注意异步任务中的错误处理（如Promise的catch、try/catch配合async/await）。

#### 注意事项

- **常见错误**  
  - 误以为异步代码会立即执行，导致逻辑顺序错误。  
  - 忘记处理Promise的reject状态，导致未捕获的异常。  
  - 在循环中错误使用异步（如for循环中使用var声明变量导致闭包问题）。

- **性能问题**  
  - 大量微任务可能导致本轮事件循环过长，延迟渲染。  
  - 定时器嵌套过深或时间过短可能造成性能损耗。

- **兼容性**  
  - Promise、async/await在旧浏览器（如IE）中需要polyfill。  
  - 微任务API（queueMicrotask）现代浏览器支持良好。

#### 代码示例

```javascript
// 同步异步混合示例
console.log(1);

setTimeout(() => console.log(2), 0);

Promise.resolve().then(() => console.log(3));

console.log(4);
// 输出：1, 4, 3, 2
```

### 2. 阻塞 vs 非阻塞

#### 概念

- **是什么**  
  阻塞和非阻塞描述的是**程序在等待调用结果时的状态**，通常针对I/O操作。  
  - **阻塞**：调用结果返回之前，当前线程被挂起（暂停执行），无法执行任何其他指令。  
  - **非阻塞**：调用不能立刻得到结果时，该调用不会挂起线程，而是立即返回一个错误、标志或当前可用的数据，线程可以继续处理其他任务。

- **为什么需要**  
  区分阻塞与非阻塞有助于理解程序在等待资源时的行为，以及如何设计高效的并发模型。在单线程JavaScript中，非阻塞I/O是其实现高并发的核心。

- **解决什么问题**  
  解决**线程闲置等待**问题，避免CPU资源浪费。

#### 原理

- **底层实现**  
  在浏览器和Node.js中，JavaScript引擎本身不直接进行I/O操作，而是将I/O请求委托给宿主环境（如libuv）。宿主环境使用多线程或系统级异步I/O接口（如epoll、kqueue）来处理，当I/O完成时通过事件循环通知JavaScript主线程。

- **工作流程**  
  1. JavaScript主线程发起一个非阻塞I/O调用（如fetch）。  
  2. 底层立即返回一个Promise对象，主线程继续执行后续代码。  
  3. 宿主环境在后台完成I/O操作，完成后将回调任务放入任务队列。  
  4. 主线程空闲时从队列中取出任务执行。

- **关键技术点**  
  - 事件驱动模型  
  - 非阻塞I/O + 事件循环  
  - 回调、Promise等异步通知机制

#### 使用方法

- **基本用法**  
  非阻塞是JavaScript异步API的默认行为，开发者无需显式指定，只需使用异步API即可。

  ```javascript
  const fs = require('fs');
  
  // 非阻塞文件读取
  fs.readFile('file.txt', (err, data) => {
    if (err) throw err;
    console.log(data);
  });
  
  console.log('读取操作已发起，继续执行其他代码');
  ```

- **常见场景**  
  - 网络请求  
  - 文件I/O（Node.js）  
  - 数据库操作  
  - 定时器

- **最佳实践**  
  - 在Node.js中始终使用异步API，避免使用同步版本（如readFileSync）导致阻塞事件循环。  
  - 使用Promise封装回调式API，便于组合和错误处理。

#### 注意事项

- **常见错误**  
  - 在Node.js中误用同步API导致性能瓶颈。  
  - 认为非阻塞就是“立即完成”，忽略回调的执行时机。

- **性能问题**  
  - 非阻塞I/O配合事件循环可以高效处理高并发，但如果回调函数执行时间过长，仍会阻塞事件循环。

- **兼容性**  
  - 浏览器和Node.js均广泛支持非阻塞I/O。

#### 代码示例

```javascript
// 阻塞示例（Node.js，不推荐）
const data = fs.readFileSync('file.txt'); // 线程阻塞直到读取完成
console.log(data);

// 非阻塞示例（推荐）
fs.readFile('file.txt', (err, data) => {
  console.log(data);
});
console.log('非阻塞调用后立即执行');
```

## 二、事件循环（Event Loop）

#### 概念

- **是什么**  
  事件循环是JavaScript实现异步并发的核心机制。它是一个不断运行的循环，负责**协调调用栈、任务队列和微任务队列**，使得单线程的JavaScript能够处理并发操作而不阻塞。

- **为什么需要**  
  由于JavaScript是单线程的，如果没有事件循环，所有任务必须同步执行，遇到耗时操作就会阻塞整个线程。事件循环允许将异步任务交给宿主环境处理，并在适当时机回调，从而实现非阻塞。

- **解决什么问题**  
  解决单线程并发问题，使JavaScript能够高效处理I/O、用户交互、定时器等异步事件。

#### 原理

- **底层实现**  
  事件循环由宿主环境（浏览器或Node.js）实现。浏览器中通常包含多个任务队列（如宏任务队列、微任务队列），并遵循一定的顺序处理它们。Node.js的libuv库提供了跨平台的事件循环实现。

- **工作流程**  
  1. 执行一个宏任务（从宏任务队列中取出一个任务）。  
  2. 执行过程中可能产生新的宏任务或微任务。  
  3. 宏任务执行完毕后，检查微任务队列，并**执行所有微任务**，直到队列为空。  
  4. 如果需要，执行UI渲染（浏览器环境）。  
  5. 从宏任务队列中取出下一个宏任务执行，重复上述步骤。

- **关键技术点**  
  - 调用栈（Call Stack）  
  - 宏任务队列（MacroTask Queue）  
  - 微任务队列（MicroTask Queue）  
  - 渲染时机（浏览器）

#### 使用方法

- **基本用法**  
  开发者不直接操作事件循环，而是通过使用异步API（setTimeout、Promise等）来利用它。理解事件循环有助于预测代码执行顺序。

- **常见场景**  
  - 调试异步代码执行顺序  
  - 优化性能（避免长任务阻塞渲染）  
  - 理解宏任务和微任务的差别

- **最佳实践**  
  - 将耗时任务拆分为多个异步步骤，避免长时间占用事件循环。  
  - 使用`queueMicrotask`或`Promise.then`来将任务推迟到当前宏任务结束后执行，但优先于下一个宏任务。  
  - 避免在微任务中递归创建微任务，导致主线程假死。

#### 注意事项

- **常见错误**  
  - 误以为setTimeout(fn, 0)会立即执行，实际上它至少会延迟到当前同步代码和微任务执行完后。  
  - 不清楚微任务和宏任务的执行顺序，导致逻辑错误。

- **性能问题**  
  - 如果微任务队列过长，会阻塞下一个宏任务和渲染。  
  - 频繁的setTimeout嵌套可能导致延迟累积。

- **兼容性**  
  - 事件循环机制在所有现代JavaScript环境中一致，但Node.js与浏览器的任务队列划分略有差异（如Node.js有`process.nextTick`，优先级高于Promise）。

#### 代码示例

```javascript
console.log('script start');

setTimeout(() => console.log('setTimeout'), 0);

Promise.resolve().then(() => console.log('promise1'));
Promise.resolve().then(() => {
  console.log('promise2');
  setTimeout(() => console.log('setTimeout inside promise'), 0);
});

console.log('script end');

// 输出顺序：
// script start
// script end
// promise1
// promise2
// setTimeout
// setTimeout inside promise
```

## 三、调用栈（Call Stack）与执行上下文

#### 概念

- **是什么**  
  - **调用栈**：一种**后进先出（LIFO）**的数据结构，用于存储代码执行期间所有处于活动状态的**执行上下文**。每当函数被调用时，其执行上下文被推入栈顶；函数返回时，该上下文被弹出。  
  - **执行上下文**：JavaScript代码执行时的环境抽象，包含变量、函数声明、作用域链和`this`的值。分为全局执行上下文、函数执行上下文和eval执行上下文。

- **为什么需要**  
  调用栈用于跟踪函数调用顺序，确保函数执行完毕后能够正确返回到调用位置。执行上下文为代码提供必要的环境信息，如变量绑定和`this`指向。

- **解决什么问题**  
  解决函数嵌套调用的管理问题，维护作用域链和变量访问权限。

#### 原理

- **底层实现**  
  当JavaScript引擎执行代码时，它会创建一个全局执行上下文并推入调用栈。每当调用一个函数，引擎会为该函数创建新的执行上下文，包含：  
  - 变量环境（存储`var`声明）  
  - 词法环境（存储`let`、`const`、函数声明）  
  - `this`绑定  
  - 外部环境引用（用于作用域链）  
  函数执行完毕后，其上下文从栈中弹出，控制权返回到上一个上下文。

- **工作流程**  
  1. 进入全局代码，创建全局执行上下文，推入栈底。  
  2. 遇到函数调用，创建该函数执行上下文，推入栈顶。  
  3. 函数内部可能继续调用其他函数，不断推入新上下文。  
  4. 函数执行完毕，其上下文从栈顶弹出，返回值交给下一个上下文。  
  5. 所有代码执行完毕，全局上下文被弹出（浏览器关闭或Node进程退出）。

- **关键技术点**  
  - 执行上下文的创建阶段（确定`this`、创建词法/变量环境）  
  - 作用域链的形成  
  - 变量提升和暂时性死区

#### 使用方法

- **基本用法**  
  开发者通常不直接操作调用栈，但理解它有助于调试递归和错误追踪。

  ```javascript
  function first() {
    second();
    console.log('first');
  }
  function second() {
    third();
    console.log('second');
  }
  function third() {
    console.log('third');
  }
  first();
  // 调用栈变化：global -> first -> second -> third (执行third) -> third弹出 -> second执行 -> second弹出 -> first执行 -> first弹出
  ```

- **常见场景**  
  - 递归函数设计  
  - 错误堆栈分析（Error.stack）  
  - 作用域链查找

- **最佳实践**  
  - 避免过深的递归，防止栈溢出。  
  - 使用尾调用优化（部分引擎支持）。  
  - 合理使用块级作用域（let/const）减少作用域链污染。

#### 注意事项

- **常见错误**  
  - **栈溢出**：递归无终止条件或调用层级过深。  
    ```javascript
    function infinite() {
      infinite();
    }
    infinite(); // RangeError: Maximum call stack size exceeded
    ```
  - 误以为函数内部声明的变量会在函数外可用（作用域链理解不清）。

- **性能问题**  
  - 频繁创建和销毁函数上下文会有微小开销，但通常可忽略。  
  - 闭包会导致上下文无法释放，可能造成内存泄漏。

- **兼容性**  
  - 调用栈机制在所有JavaScript引擎中一致。

#### 代码示例

```javascript
function a() {
  console.log('a start');
  b();
  console.log('a end');
}
function b() {
  console.log('b start');
  c();
  console.log('b end');
}
function c() {
  console.log('c');
}
a();
// 输出顺序：a start, b start, c, b end, a end
// 调用栈变化：global -> a -> b -> c -> (c弹出) -> b弹出 -> a弹出
```

## 四、宏任务（MacroTask）与微任务（MicroTask）

#### 概念

- **是什么**  
  在事件循环中，任务被细分为两种类型：  
  - **宏任务**：由宿主环境发起的任务，每个宏任务执行完后会检查微任务队列。  
  - **微任务**：由JavaScript引擎发起的任务，在当前宏任务执行完毕后、下一个宏任务开始前执行，具有更高优先级。

- **为什么需要**  
  微任务的引入是为了提供一种**更高优先级的异步调度**，使得诸如Promise回调等需要尽快执行的任务能够优先于下一批宏任务（如setTimeout）执行，保证响应性和数据一致性。

- **解决什么问题**  
  解决了任务优先级问题，确保某些任务（如状态变更、DOM更新后的操作）能在下一次事件循环之前及时执行。

#### 原理

- **底层实现**  
  事件循环维护两个队列：宏任务队列和微任务队列。  
  1. 每次从宏任务队列中取出**一个**任务执行。  
  2. 执行完当前宏任务后，立即检查微任务队列，并**执行所有微任务**（包括执行过程中新加入的微任务），直到队列清空。  
  3. 然后进行渲染（如果需要），再取下一个宏任务。

- **工作流程**  
  详见“事件循环”部分。

- **关键技术点**  
  - 宏任务来源：setTimeout、setInterval、I/O、UI渲染、script整体代码等。  
  - 微任务来源：Promise.then/catch/finally、MutationObserver、queueMicrotask、process.nextTick（Node.js）等。  
  - 微任务递归：如果微任务不断添加新微任务，会导致主线程长时间阻塞。

#### 使用方法

- **基本用法**  
  开发者通过使用对应的API来创建宏任务或微任务。  
  ```javascript
  // 创建宏任务
  setTimeout(() => console.log('macro'), 0);
  
  // 创建微任务
  Promise.resolve().then(() => console.log('micro'));
  queueMicrotask(() => console.log('micro2'));
  ```

- **常见场景**  
  - 使用微任务延迟执行但希望比setTimeout更快。  
  - 在Promise链中确保顺序。  
  - 在MutationObserver中观察DOM变化后执行清理。

- **最佳实践**  
  - 优先使用微任务（如Promise）而非宏任务（如setTimeout），除非需要特定延迟。  
  - 避免在微任务中无限循环添加微任务，导致页面卡死。  
  - 在Node.js中注意`process.nextTick`优先级高于Promise，属于特殊微任务。

#### 注意事项

- **常见错误**  
  - 混淆宏任务和微任务的执行顺序，写出不符合预期的代码。  
  - 在微任务中创建大量微任务导致主线程阻塞。

- **性能问题**  
  - 微任务队列过长会延迟渲染和下一个宏任务，影响交互响应。  
  - 宏任务过多且执行时间过长也会阻塞事件循环。

- **兼容性**  
  - Promise和MutationObserver在IE中不支持或需polyfill。  
  - queueMicrotask在现代浏览器中支持良好（IE除外）。

#### 代码示例

```javascript
console.log('1'); // 同步

setTimeout(() => console.log('2'), 0); // 宏任务

Promise.resolve().then(() => console.log('3')); // 微任务

Promise.resolve().then(() => {
  console.log('4');
  setTimeout(() => console.log('5'), 0); // 微任务内创建的宏任务
});

console.log('6'); // 同步
// 输出：1, 6, 3, 4, 2, 5
```

## 五、执行顺序（完整流程）

#### 概念

- **是什么**  
  执行顺序指在事件循环机制下，同步代码、微任务、宏任务以及渲染等步骤的综合执行次序。理解这个次序是掌握JavaScript异步行为的关键。

- **为什么需要**  
  只有准确预测代码执行顺序，才能写出可靠、无竞态条件的异步程序，避免因顺序不确定性导致的bug。

- **解决什么问题**  
  提供明确的规范，确保不同环境下（浏览器、Node.js）异步行为的一致性。

#### 原理

- **底层实现**  
  结合调用栈、宏任务队列、微任务队列和渲染阶段，事件循环按照严格规则运行。算法可简化为：  
  1. 执行一个**宏任务**（从宏任务队列头部取出）。  
  2. 执行过程中可能产生新的宏任务（入队到宏任务队列尾部）和微任务（入队到微任务队列尾部）。  
  3. 当前宏任务执行完毕，调用栈清空。  
  4. 执行所有**微任务**（从微任务队列头部依次取出执行，直到队列为空；执行过程中新产生的微任务也会在本轮清空）。  
  5. 可能进行**UI渲染**（浏览器环境，由浏览器决定是否需要渲染）。  
  6. 回到步骤1。

- **关键技术点**  
  - **先同步，再微任务，再宏任务**（但注意：整体script代码本身是一个宏任务）。  
  - 微任务优先级高于宏任务。  
  - 每一轮事件循环只执行一个宏任务，但会清空所有微任务。

#### 使用方法

- **基本用法**  
  编写代码时，根据所需延迟选择宏任务或微任务。例如，需要尽快执行但又不是同步的任务，用微任务；需要延迟一段时间的任务，用setTimeout（宏任务）。

- **常见场景**  
  - 分析复杂异步代码的输出结果。  
  - 设计需要按顺序执行的多步异步操作。  
  - 优化渲染时机，将不影响渲染的任务延迟到下一帧。

- **最佳实践**  
  - 牢记执行顺序口诀：**同步 > 微任务 > 宏任务**。  
  - 使用`await`时，后续代码相当于微任务（Promise.then）。  
  - 对于需要分割的长同步任务，可以使用setTimeout或`requestIdleCallback`将其转为宏任务，避免阻塞渲染。

#### 注意事项

- **常见错误**  
  - 误以为setTimeout(fn, 0)会在同步代码后立即执行，实际上它需要等待当前宏任务执行完且微任务清空后才可能执行。  
  - 忘记Promise构造函数中的代码是同步执行的，只有then/catch/finally是微任务。

- **性能问题**  
  - 长微任务队列会阻塞渲染，导致页面卡顿。  
  - 过度使用setTimeout可能会引入不必要的延迟。

- **兼容性**  
  - 各浏览器和Node.js版本遵循相同的HTML标准，但在具体实现细节（如渲染时机、nextTick）上存在细微差异。

#### 代码示例（综合题）

```javascript
console.log('A'); // 同步

setTimeout(() => console.log('B'), 0); // 宏任务

Promise.resolve()
  .then(() => {
    console.log('C'); // 微任务
    setTimeout(() => console.log('D'), 0); // 宏任务
  })
  .then(() => console.log('E')); // 微任务（链式）

console.log('F'); // 同步

// 执行流程：
// 1. 执行同步代码：打印 A, F
// 2. 清空微任务队列：先执行第一个then（打印 C），该then返回一个Promise，第二个then（打印 E）进入微任务队列，继续执行第二个then（打印 E）
// 3. 第一轮宏任务结束，开始第二轮宏任务：取出setTimeout回调（打印 B）
// 4. 清空微任务（无）
// 5. 第三轮宏任务：取出D所在的setTimeout回调（打印 D）
// 最终输出：A, F, C, E, B, D
```
