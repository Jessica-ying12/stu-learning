## 一、块语句

### 1. 块语句（Block Statement）

#### 概念
- **是什么**：块语句是由一对花括号 `{ }` 界定的零个或多个语句的集合。它将多个语句组合成一个复合语句，在语法上视为单个语句。
- **为什么需要**：许多控制流结构（如`if`、`for`、`while`）期望执行一个语句。当需要执行多个语句时，必须将它们组合成一个块语句。
- **解决什么问题**：解决控制流语句只能执行单条语句的限制，使得可以执行多条语句。

#### 原理
- **底层实现**：在JavaScript引擎解析时，块语句被解析为一个语句节点，内部包含一组语句列表。执行时按顺序执行列表中的语句。
- **工作流程**：遇到块语句时，进入块作用域（对于`let`/`const`），然后依次执行内部语句，最后退出块。
- **关键技术点**：块语句不改变控制流，只是语句分组；块内使用`let`/`const`声明的变量具有块级作用域。

#### 使用方法
- **基本用法**：
  ```javascript
  {
      let x = 1;
      console.log(x);
  }
  ```
- **常见场景**：与控制流语句（`if`、`for`等）结合使用，定义函数体，创建独立作用域。
- **最佳实践**：
  - 始终使用块语句包裹控制流语句的代码体（即使只有一行），提高可读性和可维护性。
  - 利用块级作用域避免变量污染。

#### 注意事项
- **常见错误**：误以为`var`声明是块级作用域，实际上`var`是函数作用域或全局作用域。
- **性能问题**：无显著性能问题。
- **兼容性**：块语句自JavaScript诞生即存在，完全兼容。块级作用域（`let`/`const`）需ES6+环境。

#### 代码示例
```javascript
// 块语句与控制流结合
if (true) {
    let message = 'Hello';
    console.log(message);
}

// 块级作用域
{
    let a = 10;
    var b = 20;
}
console.log(b); // 20，var变量泄露
// console.log(a); // 报错：a未定义
```

## 二、条件判断

### 1. if...else语句

#### 概念
- **是什么**：`if...else`语句根据一个布尔条件选择执行不同的代码块。
- **为什么需要**：实现程序的分支逻辑，根据不同条件执行不同操作。
- **解决什么问题**：解决根据条件动态选择执行路径的问题。

#### 原理
- **底层实现**：JavaScript引擎计算条件表达式，调用`Boolean()`将其转换为布尔值，根据结果跳转到对应代码块。
- **工作流程**：先计算条件，若真则执行`if`块，否则（若有`else`）执行`else`块；多个`else if`依次判断。
- **关键技术点**：条件可以是任意表达式；JavaScript的Truthy和Falsy规则决定了条件的真伪。

#### 使用方法
- **基本用法**：
  ```javascript
  if (条件) {
      // 条件为真时执行
  } else if (另一个条件) {
      // 第一个条件为假且第二个为真时执行
  } else {
      // 所有条件为假时执行
  }
  ```
- **常见场景**：用户输入验证、权限控制、根据状态显示不同UI等。
- **最佳实践**：
  - 始终使用`{}`包裹代码块，即使只有一行。
  - 避免在条件中进行赋值操作（除非明确意图并加括号）。
  - 对于复杂的多条件，考虑使用`switch`或查找表。

#### 注意事项
- **常见错误**：
  - 忘记用`===`比较，导致类型转换意外。
  - 在条件中使用赋值`=`而不是比较`==`/`===`。
- **性能问题**：`if-else`链通常性能良好，但应避免过长的链（考虑`switch`或对象映射）。
- **兼容性**：所有JavaScript环境都支持。

#### 代码示例
```javascript
let score = 85;
if (score >= 90) {
    console.log('优秀');
} else if (score >= 80) {
    console.log('良好'); // 输出
} else if (score >= 60) {
    console.log('及格');
} else {
    console.log('不及格');
}

// Truthy/Falsy示例
if ('hello') {
    console.log('字符串是真值'); // 执行
}
if (0) {
    console.log('不会执行');
}
```

### 2. switch语句

#### 概念
- **是什么**：`switch`语句对一个表达式求值，然后根据匹配的`case`标签执行相应代码，可包含`default`处理无匹配情况。
- **为什么需要**：当一个变量与多个可能值进行严格相等比较时，`switch`比`if-else`链更清晰。
- **解决什么问题**：解决多分支选择的代码可读性问题。

#### 原理
- **底层实现**：引擎计算表达式，然后按顺序将结果与每个`case`后的值进行**严格相等**（`===`）比较。一旦匹配，执行对应代码块直至遇到`break`或`switch`结束。
- **工作流程**：表达式求值 -> 依次匹配`case` -> 执行匹配的代码块 -> 遇到`break`跳出，否则继续执行后续`case`（fall-through）。
- **关键技术点**：
  - `break`控制流程跳出。
  - 允许`fall-through`实现多个值共享同一段代码。
  - `default`处理无匹配情况。

#### 使用方法
- **基本用法**：
  ```javascript
  switch (表达式) {
      case 值1:
          // 代码块1
          break;
      case 值2:
          // 代码块2
          break;
      default:
          // 默认代码块
  }
  ```
- **常见场景**：菜单选择、状态机、根据枚举值执行不同操作。
- **最佳实践**：
  - 每个`case`后都加`break`，除非有意fall-through。
  - 使用`default`处理意外情况。
  - 当`case`需要独立作用域时，用花括号包裹`case`块（ES6+）。
  - 对于需要严格相等比较的分支，优先使用`switch`。

#### 注意事项
- **常见错误**：忘记`break`导致非预期的fall-through；`case`中使用复杂表达式（`switch`匹配的是表达式的值，不是条件）。
- **性能问题**：通常`switch`比`if-else`链略快，但现代引擎优化后差异不大。
- **兼容性**：所有环境支持；独立`case`作用域需ES6+。

#### 代码示例
```javascript
let day = 3;
switch (day) {
    case 1:
        console.log('周一');
        break;
    case 2:
        console.log('周二');
        break;
    case 3:
        console.log('周三'); // 输出
        break;
    default:
        console.log('其他');
}

// fall-through
let fruit = '苹果';
switch (fruit) {
    case '香蕉':
    case '苹果':
        console.log('水果价格5元'); // 输出（因为苹果匹配后fall-through到香蕉代码？注意：如果苹果匹配，会执行香蕉代码？实际会执行第一个匹配的case，如果没有break才会向下执行。这里苹果匹配，但后面没有break，会执行苹果块和后续所有直到break。但是苹果块是空，所以会向下执行香蕉块？不，代码中'苹果'case后面没有break，所以会fall-through到下一个case（'香蕉'）的代码。因此苹果会执行香蕉的代码，这符合需求。）
        break;
    case '橙子':
        console.log('橙子价格6元');
        break;
}

// 独立作用域
switch (cmd) {
    case 'create': {
        const id = 1;
        break;
    }
    case 'delete': {
        const id = 2; // 与上面的id不冲突
        break;
    }
}
```

## 三、循环结构

### 1. for循环

#### 概念
- **是什么**：`for`循环是迭代循环，包含初始化、条件、递增/递减三个部分，适用于已知循环次数的情况。
- **为什么需要**：需要重复执行代码直到满足条件，且迭代变量规则明确。
- **解决什么问题**：简化循环代码，将循环相关表达式集中在一起。

#### 原理
- **底层实现**：引擎首先执行初始化表达式（通常声明计数器变量），然后判断条件表达式；若真则执行循环体，然后执行递增表达式，再次判断条件，如此往复直到条件为假。
- **工作流程**：初始化 -> 条件检查（真）-> 循环体 -> 递增 -> 条件检查（真）-> ... -> 条件检查（假）-> 退出循环。
- **关键技术点**：三个表达式都可选；可用`break`/`continue`控制。

#### 使用方法
- **基本用法**：
  ```javascript
  for (初始化; 条件; 递增) {
      // 循环体
  }
  ```
- **常见场景**：遍历数组、执行固定次数的操作。
- **最佳实践**：
  - 尽量使用`let`声明计数器变量，避免作用域污染。
  - 不要修改计数器变量导致意外行为。
  - 循环嵌套时注意复杂度。

#### 注意事项
- **常见错误**：忘记递增表达式导致无限循环；条件写错导致循环不执行。
- **性能问题**：数组遍历时，将数组长度缓存为变量可避免每次重新计算。
- **兼容性**：完全兼容。

#### 代码示例
```javascript
// 遍历数组
const arr = [1, 2, 3];
for (let i = 0; i < arr.length; i++) {
    console.log(arr[i]);
}

// 无限循环（用break退出）
for (;;) {
    if (Math.random() > 0.9) break;
}
```

### 2. while循环

#### 概念
- **是什么**：`while`循环在执行循环体前检查条件，条件为真时重复执行。
- **为什么需要**：适用于循环次数未知，仅依赖某个条件的情况。
- **解决什么问题**：提供一种条件驱动的循环机制。

#### 原理
- **底层实现**：每次迭代前检查条件表达式，若为真则执行循环体，然后再次检查，直到条件为假。
- **工作流程**：条件检查 -> 循环体 -> 条件检查 -> 循环体 ... -> 条件为假退出。
- **关键技术点**：条件使用Truthy/Falsy规则；循环体内应包含改变条件的操作，避免无限循环。

#### 使用方法
- **基本用法**：
  ```javascript
  while (条件) {
      // 循环体
  }
  ```
- **常见场景**：读取流数据直到结束、等待用户输入等。
- **最佳实践**：
  - 确保循环体内能改变条件，否则可能无限循环。
  - 可以使用`break`/`continue`控制。

#### 注意事项
- **常见错误**：忘记改变条件导致无限循环。
- **性能问题**：无特殊问题。
- **兼容性**：完全兼容。

#### 代码示例
```javascript
let i = 0;
while (i < 5) {
    console.log(i);
    i++;
}
```

### 3. do...while循环

#### 概念
- **是什么**：`do...while`循环先执行一次循环体，再检查条件，因此循环体至少执行一次。
- **为什么需要**：当需要至少执行一次操作，然后根据条件决定是否继续时使用。
- **解决什么问题**：保证循环体至少执行一次的场景。

#### 原理
- **底层实现**：先执行循环体，然后判断条件，若真则再次执行，否则退出。
- **工作流程**：循环体 -> 条件检查（真）-> 循环体 -> 条件检查 ... -> 条件为假退出。
- **关键技术点**：至少执行一次；条件在循环体之后检查。

#### 使用方法
- **基本用法**：
  ```javascript
  do {
      // 循环体
  } while (条件);
  ```
- **常见场景**：菜单显示至少一次、用户输入验证至少一次。
- **最佳实践**：注意条件后的分号；确保循环体内改变条件。

#### 注意事项
- **常见错误**：忘记改变条件；条件写错可能导致无限循环。
- **性能问题**：无。
- **兼容性**：完全兼容。

#### 代码示例
```javascript
let i = 10;
do {
    console.log('至少执行一次', i);
    i++;
} while (i < 5);
```

### 4. for...in循环

#### 概念
- **是什么**：`for...in`循环遍历对象的所有**可枚举属性**（包括继承的），每次迭代将属性名赋给变量。
- **为什么需要**：用于遍历对象的属性键。
- **解决什么问题**：方便地迭代对象属性。

#### 原理
- **底层实现**：引擎遍历对象的可枚举属性（包括原型链上的），按特定顺序（依赖引擎实现）依次赋值给变量，执行循环体。
- **工作流程**：获取对象及其原型链的所有可枚举属性 -> 依次赋值给变量 -> 执行循环体。
- **关键技术点**：遍历的是属性名（字符串）；包括继承的可枚举属性；不保证顺序；不应用于数组遍历。

#### 使用方法
- **基本用法**：
  ```javascript
  for (const key in object) {
      // 使用key访问属性
  }
  ```
- **常见场景**：复制对象属性、检查对象包含哪些属性。
- **最佳实践**：
  - 遍历对象属性时通常配合`hasOwnProperty`过滤原型属性。
  - 避免用于数组，因顺序不确定且可能包含非索引属性。

#### 注意事项
- **常见错误**：认为`for...in`遍历数组元素，实际上遍历的是索引字符串，可能包含意外属性。
- **性能问题**：可能较慢，尤其对象属性多或原型链长时。
- **兼容性**：完全兼容。

#### 代码示例
```javascript
const obj = { a: 1, b: 2, c: 3 };
for (const prop in obj) {
    if (obj.hasOwnProperty(prop)) {
        console.log(prop, obj[prop]);
    }
}

// 错误用法：遍历数组
const arr = [10, 20, 30];
arr.custom = 40;
for (const index in arr) {
    console.log(index, arr[index]); // 输出 0 10, 1 20, 2 30, custom 40
}
```

### 5. for...of循环 (ES6+)

#### 概念
- **是什么**：`for...of`循环遍历可迭代对象（如数组、字符串、Map、Set等）的值，每次迭代将值赋给变量。
- **为什么需要**：提供一种统一、简洁的方式遍历可迭代对象的值，避免索引操作。
- **解决什么问题**：解决遍历数据结构值时需要手动索引或迭代器的问题。

#### 原理
- **底层实现**：通过调用对象的`[Symbol.iterator]`方法获取迭代器，然后反复调用迭代器的`next()`方法，直到返回`done: true`。
- **工作流程**：获取迭代器 -> 调用`next()`，若`done`为假，则将`value`赋给变量并执行循环体 -> 重复直到`done`为真。
- **关键技术点**：只能用于可迭代对象；直接获取值，而非键或索引。

#### 使用方法
- **基本用法**：
  ```javascript
  for (const value of iterable) {
      // 使用value
  }
  ```
- **常见场景**：遍历数组元素、字符串字符、Map键值对（配合解构）、Set值等。
- **最佳实践**：
  - 使用`const`声明变量，除非需要修改。
  - 配合解构遍历Map：`for (const [key, value] of map)`

#### 注意事项
- **常见错误**：对普通对象使用`for...of`会报错（对象不可迭代）。
- **性能问题**：通常比`for`循环稍慢（因迭代器开销），但可读性更好。
- **兼容性**：ES6+环境支持。

#### 代码示例
```javascript
const arr = [1, 2, 3];
for (const num of arr) {
    console.log(num);
}

const str = 'hello';
for (const ch of str) {
    console.log(ch);
}

const map = new Map([['a',1], ['b',2]]);
for (const [key, value] of map) {
    console.log(key, value);
}
```

### 6. for await...of循环 (ES2018+)

#### 概念
- **是什么**：`for await...of`循环用于遍历异步可迭代对象（如异步生成器、异步可迭代对象），等待每次迭代的Promise解决。
- **为什么需要**：处理异步数据流（如从网络分批获取数据、读取文件流）时，需要异步迭代。
- **解决什么问题**：提供在异步上下文中迭代异步数据源的能力。

#### 原理
- **底层实现**：调用对象的`[Symbol.asyncIterator]`获取异步迭代器，然后每次迭代等待`next()`返回的Promise解决，将解决值赋给变量。
- **工作流程**：获取异步迭代器 -> 等待`next()`的Promise，若`done`为假，则将`value`赋给变量并执行循环体 -> 重复直到`done`为真。
- **关键技术点**：必须在异步函数或模块顶层使用；处理异步数据流。

#### 使用方法
- **基本用法**：
  ```javascript
  for await (const variable of asyncIterable) {
      // 使用variable
  }
  ```
- **常见场景**：遍历异步生成器返回的数据、读取异步流。
- **最佳实践**：配合异步生成器使用；注意错误处理（可用`try...catch`）。

#### 注意事项
- **常见错误**：在非异步上下文中使用会报错；忘记`await`。
- **性能问题**：由于异步等待，可能影响整体执行时间。
- **兼容性**：ES2018+，Node.js 10+，现代浏览器。

#### 代码示例
```javascript
async function* asyncGenerator() {
    yield 1;
    yield 2;
    yield 3;
}

(async () => {
    for await (const num of asyncGenerator()) {
        console.log(num);
    }
})();
```

## 四、循环控制

### 1. break语句

#### 概念
- **是什么**：`break`语句立即终止当前循环或`switch`语句，程序控制流转到循环或`switch`后的下一条语句。
- **为什么需要**：在满足某些条件时提前退出循环或`switch`，避免不必要的迭代。
- **解决什么问题**：实现循环的提前终止。

#### 原理
- **底层实现**：当执行`break`时，引擎跳出当前最内层循环或`switch`，并将程序计数器指向该结构后的下一条指令。
- **工作流程**：执行`break` -> 终止当前循环/`switch` -> 跳转到之后代码。
- **关键技术点**：可带标签跳出指定外层语句。

#### 使用方法
- **基本用法**：`break;` 或 `break label;`
- **常见场景**：在搜索到目标后退出循环；提前结束`switch`。
- **最佳实践**：
  - 避免过多使用`break`，以免降低可读性。
  - 在嵌套循环中使用标签明确跳出哪一层。

#### 注意事项
- **常见错误**：忘记`break`导致fall-through（在`switch`中）；标签错误导致语法错误。
- **性能问题**：无。
- **兼容性**：完全兼容；标签需ES3+。

#### 代码示例
```javascript
// 基础break
for (let i = 0; i < 10; i++) {
    if (i === 5) break;
    console.log(i); // 0,1,2,3,4
}

// 带标签
outer: for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (i === 1 && j === 1) break outer;
        console.log(i, j);
    }
}
```

### 2. continue语句

#### 概念
- **是什么**：`continue`语句跳过当前循环迭代的剩余代码，直接开始下一次迭代。
- **为什么需要**：在循环中当某些条件满足时，忽略后续处理，继续下一轮。
- **解决什么问题**：实现循环中部分代码的有条件跳过。

#### 原理
- **底层实现**：执行`continue`时，引擎立即跳转到循环的递增表达式（`for`）或条件检查（`while`/`do...while`），开始下一次迭代判断。
- **工作流程**：遇到`continue` -> 跳过当前迭代剩余代码 -> 进入循环的下一次迭代（`for`先执行递增，再检查条件）。
- **关键技术点**：可带标签跳过到外层循环的下一轮。

#### 使用方法
- **基本用法**：`continue;` 或 `continue label;`
- **常见场景**：过滤某些元素，跳过不处理。
- **最佳实践**：与`break`一样，避免过度使用，保持逻辑清晰。

#### 注意事项
- **常见错误**：在`while`循环中忘记更新计数器导致无限循环；标签错误。
- **性能问题**：无。
- **兼容性**：完全兼容。

#### 代码示例
```javascript
// 基础continue
for (let i = 0; i < 5; i++) {
    if (i === 2) continue;
    console.log(i); // 0,1,3,4
}

// 带标签
outer: for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (i === 1 && j === 1) continue outer;
        console.log(i, j);
    }
}
```

## 五、异常处理

### 1. throw语句

#### 概念
- **是什么**：`throw`语句抛出一个用户自定义的异常。执行`throw`时，当前函数执行停止，控制权传递给最近的`catch`块。
- **为什么需要**：当程序遇到无法恢复的错误或异常情况时，需要主动抛出错误，让上层处理。
- **解决什么问题**：提供主动报告错误机制，分离业务逻辑与错误处理。

#### 原理
- **底层实现**：引擎创建一个异常对象并开始向上展开调用栈，寻找匹配的`catch`块；如果找不到，程序终止。
- **工作流程**：执行`throw` -> 暂停当前执行 -> 将异常对象传递给最近的`catch`（如果有）-> 否则程序崩溃。
- **关键技术点**：可以抛出任意类型，但通常抛出`Error`对象或其子类，以便获得堆栈信息。

#### 使用方法
- **基本用法**：`throw 表达式;`
- **常见场景**：参数校验失败、操作无法继续、自定义错误类型。
- **最佳实践**：
  - 使用`Error`对象或继承自`Error`的类，提供明确的错误信息。
  - 在抛出点给出足够上下文。

#### 注意事项
- **常见错误**：抛出原始类型（如字符串）导致堆栈丢失；不处理未捕获异常导致程序崩溃。
- **性能问题**：频繁抛出异常会影响性能，应仅用于异常情况。
- **兼容性**：完全兼容。

#### 代码示例
```javascript
function divide(a, b) {
    if (b === 0) {
        throw new Error('除数不能为0');
    }
    return a / b;
}

try {
    divide(10, 0);
} catch (e) {
    console.error(e.message); // 除数不能为0
}
```

### 2. try...catch...finally语句

#### 概念
- **是什么**：`try...catch...finally`语句用于捕获并处理异常，`finally`块无论是否捕获都会执行。
- **为什么需要**：使程序在发生异常时能优雅恢复或清理资源，避免崩溃。
- **解决什么问题**：结构化异常处理，分离正常逻辑与错误处理。

#### 原理
- **底层实现**：`try`块中的代码在监控下执行；若抛出异常，控制转移到对应的`catch`块；无论是否异常，最后执行`finally`块。
- **工作流程**：执行`try`块 -> 若无异常，跳过`catch` -> 执行`finally` -> 继续后续代码。若有异常，立即跳转到`catch`块（如果有），然后执行`finally`。
- **关键技术点**：
  - `catch`块接收异常参数。
  - `finally`块总会执行，甚至`try`或`catch`中有`return`、`break`等。
  - 可以省略`catch`或`finally`，但不能都省略。

#### 使用方法
- **基本用法**：
  ```javascript
  try {
      // 可能抛出异常的代码
  } catch (error) {
      // 处理异常
  } finally {
      // 清理代码
  }
  ```
- **常见场景**：资源释放（文件关闭、网络连接）、错误恢复、日志记录。
- **最佳实践**：
  - 只捕获能处理的异常，否则重新抛出。
  - 使用`finally`清理资源，避免资源泄露。
  - `catch`块中避免抛出无信息的错误。

#### 注意事项
- **常见错误**：在`finally`中使用`return`会覆盖`try`或`catch`中的返回值；忽略异步代码中的异常（需用Promise catch）。
- **性能问题**：`try...catch`有一定开销，但现代引擎优化后影响小，不应用于常规控制流。
- **兼容性**：完全兼容。

#### 代码示例
```javascript
let file;
try {
    file = openFile();
    // 操作文件
    if (error) throw new Error('文件损坏');
} catch (e) {
    console.error('处理文件出错:', e);
    // 可能重新抛出
    // throw e;
} finally {
    if (file) closeFile(file);
}

// finally覆盖return的例子
function test() {
    try {
        return 'try';
    } finally {
        return 'finally'; // 覆盖try的return
    }
}
console.log(test()); // 'finally'
```

## 六、其他相关语句

### 1. return语句

#### 概念
- **是什么**：`return`语句指定函数返回的值，并立即终止函数执行。
- **为什么需要**：函数需要输出结果或提前结束。
- **解决什么问题**：提供函数输出机制，控制函数流程。

#### 原理
- **底层实现**：执行`return`时，引擎计算表达式值（若无则返回`undefined`），然后展开调用栈，将值返回给调用者。
- **工作流程**：执行`return` -> 计算返回值 -> 退出当前函数 -> 将返回值传递给调用处。
- **关键技术点**：可在任何地方使用；如果没有`return`，函数默认返回`undefined`。

#### 使用方法
- **基本用法**：`return;` 或 `return 表达式;`
- **常见场景**：函数返回值、提前退出函数。
- **最佳实践**：
  - 确保所有路径都有明确的返回（尤其是在有条件的函数中）。
  - 避免在构造函数中忘记`return`（但构造函数默认返回`this`）。

#### 注意事项
- **常见错误**：忘记返回值导致`undefined`；在`return`后写代码（永远不会执行）。
- **性能问题**：无。
- **兼容性**：完全兼容。

#### 代码示例
```javascript
function add(a, b) {
    return a + b;
}
let result = add(2, 3); // 5

function earlyExit(num) {
    if (num < 0) return; // 返回undefined
    return num * 2;
}
```

### 2. debugger语句

#### 概念
- **是什么**：`debugger`语句调用任何可用的调试功能，如断点。若无调试功能，语句无效。
- **为什么需要**：在代码中手动设置断点，便于调试。
- **解决什么问题**：提供一种编程方式触发调试器暂停。

#### 原理
- **底层实现**：当执行到`debugger`时，如果调试器已连接，则暂停执行；否则忽略。
- **工作流程**：执行`debugger` -> 检查是否有调试器 -> 有则暂停，否则继续。
- **关键技术点**：不影响生产环境（通常会被忽略，但最好在发布前移除）。

#### 使用方法
- **基本用法**：`debugger;`
- **常见场景**：调试复杂逻辑，希望在该处暂停检查状态。
- **最佳实践**：仅在开发阶段使用；不要提交到生产代码。

#### 注意事项
- **常见错误**：忘记移除生产代码中的`debugger`，可能导致程序暂停（如果开发者工具打开）。
- **性能问题**：无，但暂停会阻塞程序。
- **兼容性**：完全兼容。

#### 代码示例
```javascript
function calculate(value) {
    let temp = value * 2;
    debugger; // 调试器会在此暂停
    return temp + 1;
}
```

### 3. label语句

#### 概念
- **是什么**：标签语句为一条语句提供一个标识符，可与`break`或`continue`一起使用，跳转到指定语句。
- **为什么需要**：在嵌套循环中，需要跳出多层循环或指定继续的循环。
- **解决什么问题**：提供更精细的流程控制。

#### 原理
- **底层实现**：标签标记了一个语句的位置，`break label`或`continue label`可以跳转到该标签对应的语句（必须与循环或`switch`关联）。
- **工作流程**：定义标签 -> 在循环或`switch`中使用带标签的`break`/`continue`。
- **关键技术点**：标签只能用于`break`/`continue`，且`break`可用于任何带标签的语句，`continue`只能用于循环标签。

#### 使用方法
- **基本用法**：
  ```javascript
  label: 语句
  ```
- **常见场景**：跳出嵌套循环。
- **最佳实践**：谨慎使用，避免代码难以理解。通常可通过提取函数等方式简化。

#### 注意事项
- **常见错误**：试图`continue`到非循环标签；标签名与变量名冲突（标签作用域独立）。
- **性能问题**：无。
- **兼容性**：完全兼容。

#### 代码示例
```javascript
outerLoop: for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (i === 1 && j === 1) {
            break outerLoop; // 跳出外层循环
        }
        console.log(i, j);
    }
}
```
