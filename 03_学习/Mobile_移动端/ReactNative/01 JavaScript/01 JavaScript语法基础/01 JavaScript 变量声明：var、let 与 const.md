## 一、var声明

### 概念
- **是什么**：`var` 是 JavaScript 中声明变量的传统关键字，在 ES6 之前是主要方式。它用于在函数或全局作用域中创建变量，存储数据值。
- **为什么需要**：提供基础的变量存储和访问机制，是早期 JavaScript 程序构建的基石。
- **解决什么问题**：允许开发者在代码中创建可变的命名存储单元，实现数据的暂存和传递。

### 原理
- **底层实现**：在 JavaScript 引擎执行代码时，会先创建执行上下文。对于 `var` 声明的变量，引擎会在进入执行上下文时（预编译阶段）将其添加到**变量环境**中，并初始化为 `undefined`。这个过程称为**变量提升**。当执行到赋值语句时，引擎会更新变量环境中的对应值。
- **工作流程**：
  1. 创建阶段：引擎扫描函数和 `var` 声明，将变量名加入变量环境，赋值为 `undefined`。
  2. 执行阶段：逐行执行代码，遇到赋值语句则修改变量值。
- **关键技术点**：
  - **函数作用域**：变量的作用域由最近的函数决定，而非代码块。
  - **变量提升**：声明被提升到作用域顶部，但赋值留在原地。
  - **可重复声明**：同一作用域内可多次声明同一变量，后续声明被忽略但赋值会覆盖。
  - **全局对象属性**：在全局作用域用 `var` 声明的变量会成为全局对象的属性（如浏览器的 `window`）。

### 使用方法
- **基本用法**：
  ```javascript
  var name;               // 声明，默认值为 undefined
  var age = 25;           // 声明并初始化
  var x = 1, y = 2, z;    // 一次性声明多个变量
  ```
- **常见场景**：
  - 在 ES6 之前用于所有变量声明。
  - 在旧代码库或需要兼容老旧浏览器时遇到。
- **最佳实践**：
  - 在现代 JavaScript 开发中，**应避免使用 `var`**，使用 `let` 和 `const` 代替。
  - 如果必须使用，确保变量声明在作用域顶部，以模拟块级作用域效果。
  - 始终在严格模式下编写代码，防止意外创建全局变量。

### 注意事项
- **常见错误**：
  - 忽略块级作用域导致的变量泄漏：例如在 `for` 循环中用 `var` 声明迭代变量，循环结束后变量仍然存在。
  - 变量提升导致的值意外为 `undefined`：在声明前使用变量不会报错，但值为 `undefined`。
  - 重复声明覆盖变量值而不报错，可能隐藏逻辑错误。
  - 未声明直接赋值会创建隐式全局变量（非严格模式下），造成污染。
- **性能问题**：`var` 本身性能无差异，但因其作用域特性可能导致意外变量保持，影响内存释放（如循环中的变量在外部仍可访问，无法被垃圾回收）。
- **兼容性**：所有 JavaScript 环境均支持 `var`，兼容性最好。

### 代码示例
```javascript
// 变量提升示例
console.log(myVar); // 输出: undefined
var myVar = 10;

// 函数作用域示例
function test() {
    if (true) {
        var insideIf = "block";
    }
    console.log(insideIf); // 输出: "block"，无块级作用域
}
test();

// 重复声明示例
var count = 1;
var count = 2; // 允许，count 变为 2
console.log(count); // 2

// 全局对象属性
var globalVar = "hello";
console.log(window.globalVar); // "hello" (浏览器环境)

// 隐式全局变量（非严格模式）
function bad() {
    leaked = "global";
}
bad();
console.log(leaked); // "global" (污染全局)
```

## 二、let声明

### 概念
- **是什么**：`let` 是 ES6 引入的新的变量声明关键字，用于声明块级作用域的变量。
- **为什么需要**：为了解决 `var` 的函数作用域、变量提升和重复声明等问题，提供更精确的变量控制。
- **解决什么问题**：
  - 限制变量作用域到代码块，避免变量泄漏。
  - 消除变量提升带来的混乱（暂时性死区）。
  - 禁止同一作用域内重复声明，避免意外覆盖。

### 原理
- **底层实现**：在执行上下文中，`let` 声明的变量存储在**词法环境**中，而不是变量环境。创建阶段引擎会记录 `let` 变量，但**不会初始化**，变量处于未初始化状态。这意味着在声明之前访问会导致引用错误（暂时性死区）。执行阶段当执行到 `let` 声明语句时，引擎会为变量分配内存并初始化为指定的值（若无指定则为 `undefined`）。
- **工作流程**：
  1. 进入作用域（如函数、块），引擎创建词法环境并注册 `let` 变量，但不初始化，进入 TDZ。
  2. 执行到声明语句前，任何对该变量的访问都会触发 `ReferenceError`。
  3. 执行声明语句，变量被初始化，离开 TDZ，之后可正常使用。
  4. 当离开作用域（如块结束），变量被销毁。
- **关键技术点**：
  - **块级作用域**：由 `{}` 界定。
  - **暂时性死区（TDZ）**：从块开始到声明语句之间的区域。
  - **不允许重复声明**：同一作用域内只能声明一次。
  - **循环中的特殊处理**：`for` 循环中用 `let` 声明迭代变量，每次迭代都会创建一个新的绑定。

### 使用方法
- **基本用法**：
  ```javascript
  let name;           // 声明，默认 undefined
  let age = 25;       // 声明并初始化
  let x = 1, y = 2;   // 声明多个
  ```
- **常见场景**：
  - 任何需要重新赋值的变量，如计数器、累加器、状态标志。
  - 在块级作用域内需要局部变量时（如 `if`、`for` 内部）。
  - 取代 `var` 的所有场景。
- **最佳实践**：
  - **优先使用 `const`，只在变量值需要改变时使用 `let`**。
  - 尽量缩小变量的作用域，在最小块内声明。
  - 声明时尽量同时初始化，避免 TDZ 混淆。

### 注意事项
- **常见错误**：
  - 在声明前访问变量（TDZ 错误）：
    ```javascript
    console.log(myLet); // ReferenceError
    let myLet = 5;
    ```
  - 在同一作用域内重复声明：
    ```javascript
    let a = 1;
    let a = 2; // SyntaxError
    ```
  - 误以为 `let` 在 `for` 循环中会被提升到函数顶部（实际是每次迭代创建新绑定）。
- **性能问题**：`let` 的性能与 `var` 几乎无差异，但块级作用域有助于垃圾回收，可能带来内存优化。
- **兼容性**：支持 ES6 的环境均支持 `let`（IE11 不支持，但现代浏览器和 Node.js 均支持）。可通过 Babel 等工具转译以兼容旧环境。

### 代码示例
```javascript
// 块级作用域与 TDZ
function testLet() {
    // console.log(x); // ReferenceError: Cannot access 'x' before initialization
    let x = 10;
    if (true) {
        let x = 20; // 独立的块级变量
        console.log(x); // 20
    }
    console.log(x); // 10
}
testLet();

// 不允许重复声明
let y = 1;
// let y = 2; // SyntaxError

// for 循环中的 let
for (let i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 0); // 输出 0,1,2
}

// 全局作用域不挂载到 window
let globalLet = "not on window";
console.log(window.globalLet); // undefined
```

## 三、const声明

### 概念
- **是什么**：`const` 是 ES6 引入的关键字，用于声明**常量**，即一旦声明赋值后，其绑定不可改变。
- **为什么需要**：提供一种方式表达“该变量不会被重新赋值”的意图，增强代码可读性和可维护性，同时防止意外修改。
- **解决什么问题**：
  - 避免常量被无意修改，提高代码安全性。
  - 明确标识只读变量，便于开发者理解变量用途。
  - 与 `let` 一样，具有块级作用域和 TDZ，解决 `var` 的问题。

### 原理
- **底层实现**：`const` 声明也存储在词法环境中，与 `let` 类似，但多了一个约束：一旦初始化后，其绑定的值不可变。这里的“不可变”是指**变量标识符与值的绑定不可变**，即不能通过赋值改变变量的引用。对于基本类型（值本身），意味着值不可变；对于引用类型（对象、数组），变量指向的内存地址不可变，但对象内部属性可以改变。实现上，引擎会在 `const` 变量对应的内存位置设置一个“只读”标志，当尝试赋值时会抛出 `TypeError`。
- **工作流程**：
  1. 进入作用域，引擎注册 `const` 变量，不初始化，进入 TDZ。
  2. 执行到 `const` 声明语句，必须提供一个初始值，引擎分配内存并设置只读标志。
  3. 后续任何赋值操作都会触发运行时错误。
  4. 离开作用域，变量销毁。
- **关键技术点**：
  - **必须初始化**：声明时必须有初始值。
  - **绑定不可变**：不能重新赋值。
  - **引用类型的内容可变**：修改对象属性或数组元素是允许的。
  - **块级作用域与 TDZ**：与 `let` 相同。

### 使用方法
- **基本用法**：
  ```javascript
  const PI = 3.14159;          // 声明并初始化
  // const MAX;                // 报错: Missing initializer
  const USER = { name: "Alice" };
  const NUMBERS = [1, 2, 3];
  ```
- **常见场景**：
  - 声明配置常量、数学常数、固定路径等不会改变的值。
  - 声明函数表达式、对象、数组等，只要不重新赋值整个变量。
  - 在 `for...of` 和 `for...in` 循环中作为迭代变量（每次迭代创建新的绑定）。
- **最佳实践**：
  - **默认使用 `const`**：除非确实需要重新赋值，否则都用 `const`。这使代码意图明确，且防止误修改。
  - 对于引用类型，若希望内容也不可变，可使用 `Object.freeze()`（浅冻结）或 TypeScript 的 `readonly` 修饰符。
  - 不要使用 `const` 声明应在循环中改变的变量（如 `for` 循环计数器）。

### 注意事项
- **常见错误**：
  - 忘记初始化：
    ```javascript
    const C; // SyntaxError
    ```
  - 尝试重新赋值：
    ```javascript
    const C = 10;
    C = 20; // TypeError
    ```
  - 误以为 `const` 对象不可变，修改属性后意外行为：
    ```javascript
    const obj = { a: 1 };
    obj.a = 2; // 允许，但可能不符合某些开发者的预期
    ```
  - 在 `for` 循环中使用 `const` 作为迭代变量（除非是 `for...of`）：
    ```javascript
    for (const i = 0; i < 3; i++) {} // i++ 尝试修改 i，报错
    ```
- **性能问题**：`const` 可能有助于引擎优化，因为知道绑定不会改变（尤其是基本类型），但实际差异微小。
- **兼容性**：与 `let` 相同，支持 ES6 的环境均支持（IE11 不支持），可转译。

### 代码示例
```javascript
// 基本类型不可重新赋值
const SPEED = 100;
// SPEED = 200; // TypeError

// 引用类型内容可修改
const PERSON = { name: "Bob" };
PERSON.name = "Alice"; // 允许
console.log(PERSON.name); // "Alice"
// PERSON = { name: "Charlie" }; // TypeError: 不能重新赋值

const ARR = [1, 2, 3];
ARR.push(4); // 允许
console.log(ARR); // [1,2,3,4]
// ARR = [5,6,7]; // TypeError

// 块级作用域与 TDZ
if (true) {
    // console.log(TEMP); // ReferenceError: TDZ
    const TEMP = 36.5;
    console.log(TEMP); // 36.5
}
// console.log(TEMP); // ReferenceError: 不在作用域内

// for...of 中使用 const
for (const elem of ['a','b']) {
    console.log(elem); // 输出 'a','b'，每次迭代新绑定
}
```
